一家公司给员工配备 AI 编程工具，账单会有多大？[《The Information》的报道](https://www.theinformation.com/articles/meta-microsoft-work-wean-staff-anthropics-claude)给出一个数字：Meta 的 Claude Code 账单超过 **1.05 亿美元**，账单周期为 28 天。报道依据是 Meta 内部数据。这个数字不对应 Anthropic 的季度收入；Meta 全部 AI 费用另有口径。

同一篇报道指出，Meta 和微软削减员工对 Claude 的依赖。两家公司没有宣布禁用 Claude。员工用量、客户用量、预算上限和实际支出，各有口径。

## Meta：Claude Code 用户数减半

《The Information》查阅的内部数据显示，Meta 的 Claude Code 年初用户数约 **6 万人**，近期用户数约 **3 万人**。春季裁员解释其中一部分变化。自研工具改变了员工选择：Muse Code 的内部用户超过 6000 人；MetaCode 的内部用户超过 3 万人。两款工具与 Claude Code 的用户群存在重叠风险，人数不能相加。

Meta 的费用数字呈现另一面：用户数下降，账单规模仍高。28 天超过 1.05 亿美元，属于 Claude Code 的一个观察周期。它不能充当全年费用，也不能推算单个员工的平均成本。团队规模、任务类型、模型选择和缓存机制都会改变费用。

![Meta 内部 Claude Code 用户数与 28 天费用：两组数字采用不同口径](/article-images/meta-microsoft-claude-internal-costs/meta-usage.webp)

## 微软：预测下调，不等于 Claude 退出

报道援引知情人士称，微软的内部 Anthropic 技术年化支出预测至少 **10 亿美元**。微软把这项预测下调超过三分之一。这里的 10 亿美元是预测值，不是已支付的全年账单。

微软云与 AI 部门调整了员工的模型费用额度。旧月度个人上限为 **10 万美元**；多数员工的新上限约为 **1 万美元**。这个上限覆盖各类 AI 模型，不是 Claude 专属；上限变化不能证明每名员工花掉 10 万美元。

微软发言人确认，公司将内部 AI 编程的默认模型改为 OpenAI 模型，引导员工使用 GitHub Copilot。工程师保留 Claude 的选择权。微软鼓励员工使用自家编程产品，产品改进构成另一项原因。

## 两本账：内部成本与客户需求

微软员工使用 Claude 产生内部成本。微软客户使用 Claude 驱动的 Copilot 功能，构成另一条需求。报道指出，客户侧的 Anthropic 模型费用呈增长态势；这部分费用抵消了部分内部用量削减。内部预算收紧无法证明“微软停止采购 Claude”。这项变化无法证明“Claude 失去企业市场”。

![微软内部使用与客户使用：成本口径和需求方向各不相同](/article-images/meta-microsoft-claude-internal-costs/two-ledgers.webp)

这件事呈现一项采购变化。企业把 AI 编程额度纳入生产力投入。高额账单要求新的管理方式：团队预算、模型路由、任务分级和效果核算。自研工具提供一个成本选择，外部模型保留一个能力选择。二者可以共存。

《The Information》的数据来自内部文件和知情人士，Meta 没有对报道发表评论。数字反映特定公司与特定时期，不构成行业平均值。企业需要两个指标：每项任务消耗多少成本，交付质量换来多少收益。
