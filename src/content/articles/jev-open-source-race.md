AI 决策模型 Jev 的接口神秘感维持了六天。

八个开源项目出现。四条技术路线成形。最小方案读取现成模型的下一个 token 概率；专用模型方案使用 1.51 亿至 4.21 亿参数；大模型方案加入 LoRA 与指针头；扩散模型方案放弃自回归文本。

这轮复刻给出清晰结论：Jev 的 API 门槛低。概率校准、跨域准确率和高候选数稳定性门槛高。

![四条技术路线汇入概率校准核心](/article-images/jev-open-source-race/cover.webp)

## 四条路线，八种答案

TypeSafe AI 的 Jev 发布日是 2026 年 9 月 15 日。官方定义是首个 System One Model。输入包含状态、问题与候选项，输出包含类型结果与概率。自由文本离开输出层，软件获得可执行判断。

开源社区接受了这个接口命题。模型实现出现分流。

![Jev开源复刻的四条技术路线](/article-images/jev-open-source-race/routes.webp)

### 路线一：读取 Logit

SemIf 与 Simple Jev 选择低成本方案。现成模型接收状态、问题和候选项，程序读取候选 token 的 Logit。分数归一化产生概率。

SemIf 使用 Qwen3.5-4B。项目测试包含同一模型、同一状态和 21 个二元问题。Logit 路径耗时 1.023 秒，紧凑 JSON 数组生成耗时 5.332 秒。一致项数量为 18。

这个差异关系重大。输出路径变短，语义判断存在差异。

Simple Jev 加入公共前缀复用与批量后缀计算。一次预填充支撑多道问题的共享缓存。项目文档承认一个边界：返回分数缺少校准正确率的含义。

接口复制完成。概率可信问题保留。

### 路线二：训练专用编码器

Laya、Von 与 Verdict 抛弃生成式骨架。ModernBERT 一类编码器负责状态理解，分类头负责候选项打分。参数量下降，延迟进入数十毫秒区间。

Laya 提供 3.22 亿和 4.21 亿参数版本。项目测试给出 32.8 至 39.5 毫秒延迟。Banking77 测试结果包含两个数字：Laya 得分 42.5%，Jev 公布值为 87%。两者候选标签数量存在差异，这组数字提供能力尺度。

Verdict 的参数量是 1.51 亿。项目自有分布测试得到 95% 准确率。外部 TypeSafe 用例测试给出另一幅图景：Verdict 为 48.07%，26B DiffusionGemma 为 88.43%，Jev 为 90.80%。样本总量是 337。

候选数量带来另一道压力。Verdict 的三候选准确率为 97%，十七候选准确率为 78%，二十五候选准确率为 72%。候选顺序变换造成 4.5% 的答案翻转。

小模型获得速度。本域数据决定能力上限。

### 路线三：改造大语言模型

Kev 与 Nimble 的骨架来自 Qwen。新增组件承担决策训练。

Kev 覆盖 8 亿、40 亿和 90 亿参数。LoRA 与指针头负责候选项选择。90 亿参数版本的新来源开发集准确率是 81.2%，Jev 是 85.7%。Kev 的高置信错误比例是 7.5%：模型概率超过 0.9，答案错误。

日期运算暴露能力损失。基础 Qwen3.5-9B 的准确率是 82%，Kev 微调版本是 72%。决策微调提升部分任务，原有能力损伤风险存在。

Nimble 使用 2676 条训练样本。数据含事实翻转对：一处事实变化触发正确标签变化。324 条留出样本的结果是 Nimble 90.12%，Jev 93.21%，基础 Qwen3.5-9B 66.36%。

能力差距缩至 3.09 个百分点。数据限制明确：标签来自合成流程，样本缺少人工复核，输出概率缺少校准。

### 路线四：扩散模型填空

OpenJev 选择 DiffusionGemma-26B。模型把答案位置视为待填空白。离散扩散承担并行去噪。方案输出候选项，说明文本缺席。

项目方测试使用 RTX PRO 6000。单并发中位延迟是 94 毫秒。64 并发中位延迟是 760 毫秒，P95 是 1109 毫秒。模型权重占用为 18GB。

项目的置信度来自归一化熵。低熵代表模型态度集中。正确率结论缺乏依据。熵分数与校准概率属于两种东西。

## 低延迟成为公共能力

八个项目证明了一个工程事实：结构化判断脱离完整文本生成具有可行性。

候选 Logit、编码器分类头、指针头和扩散填空消除长输出。共享状态消除重复预填充。Jev 的产品定义获得开源验证。

TypeSafe 的官方工作流给出 193.6 倍速度与 444.6 倍成本优势。官方文章说明，这组数字位于真实场景收益的高端。评测来自厂商工作流，参考答案来自前沿模型平均值。

速度命题获得开源测试支持。竞争焦点转向质量命题。

## 概率可信需要四项证据

一个模型输出 0.9。这个数字控制付款放行、告警关闭或工具执行。这个数字承担权限。

可信概率需要四项证据。

第一项是准确率。结果受候选项数量、任务领域和语言影响。单一平均分缺少生产负载代表性。

第二项是校准曲线。0.9 置信样本的正确率需要接近 90%。高置信错误数量决定自动执行风险。

第三项是分布迁移。新来源数据、同义改写、选项重排和难负例构成压力测试。Verdict 的拒答召回率变化是 75.5%→18%，原因是难负例集合。

第四项是策略阈值。模型输出概率，代码决定权限。高置信结果进入自动分支，中置信结果进入复核队列，低置信结果进入拒答路径。阈值需要业务损失函数支持。

API 对结果形状负责。训练与评测对概率含义负责。

## Jev 的护城河换了位置

公开材料缺少 Jev 的模型架构、训练数据和 RLCD 细节。未知配方的复制条件缺席。八个项目复制了产品接口，接口之外的难度获得曝光。

Logit 方案适合原型验证。专用编码器适合固定领域与低算力环境。大模型改造适合高准确率需求。扩散路线适合并行解码研究。每条路线需要自有数据集与校准测试。

开源复刻保留 Jev 的价值。证明题难度上升：封闭训练与跨领域可信概率的关系需要证据。

决策模型的竞争离开 JSON 格式。下一站是概率可信。
