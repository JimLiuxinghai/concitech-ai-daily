一个主题，一份 PDF，一间教室。

OpenMAIC 接收前两个，系统生产第三个。

老师讲课，同学插话，白板出现图形，测验打断讲解。学生提出问题，几名 AI 角色接住问题。课件支持 PPTX 导出，互动场景支持 HTML 导出。

这玩意超出聊天框的边界。

它像一套课堂生成器。

一条 X 推文介绍了这个项目。推文数据包含 61 万次观看、4130 个点赞和 1108 次转发。文案宣告一批教育创业公司的死亡。

这个判断有流量味道。我的判断降低戏剧感，保留疼痛感。

教育公司存活。OpenMAIC 击穿了课程生产工具的价格地板。

![OpenMAIC 项目视觉，图片来源 OpenMAIC GitHub 仓库](/article-images/openmaic-ai-classroom/official-banner.webp)

OpenMAIC 全名是 Open Multi-Agent Interactive Classroom。清华大学团队创建了仓库。仓库创建日期是 2026 年 3 月 11 日。X 推文发布日期是 3 月 17 日。

六个月后的 GitHub 页面给出一组数字。星标数是 35,286，复刻数是 5,630，贡献者接口返回 84 个名字。仓库许可证是 MIT。采集日期是 2026 年 9 月 11 日。

这组数字与教学效果分属两个命题。它证明了一件事，开发者需求存在，需求密度显出强度。

OpenMAIC 的输入形式包括主题和材料。材料类型包括文档、音频、视频。系统规划课程结构，生成页面，安排测验，组织角色。教师 Agent 负责讲解，同学 Agent 负责讨论，导演式编排负责轮次与场景。

课件构成骨架。

课堂构成产品。

普通课件生成器交付一叠页面。OpenMAIC 交付一个过程。页面承担讲解，测验承担检查，互动组件承担操作，项目制任务承担迁移。语音合成赋予角色声音，语音识别接收学生问题，白板动作承担公式和图形表达。

这套设计击中了网络学习的老毛病。

视频课程拥有优秀老师与精美剪辑。学生按下播放键。孤独感存在。知识流向学生。回应数量稀少。弹幕提供热闹。热闹缺少教学互动。

OpenMAIC 给课堂增加了几种声音。老师提问，同学表达误解，另一名同学补充线索，用户进入讨论。一个人的自学页面长出同桌。

![OpenMAIC 测验和多角色讨论界面，图片来源 OpenMAIC GitHub 仓库](/article-images/openmaic-ai-classroom/discussion.webp)

这个设计并非一次产品脑洞。

清华团队的一篇 NAACL 2025 论文介绍了 SimClass。研究包含两门真实课程，参与学生超过 400 人。研究团队邀请了 48 名学生参加消融实验。论文使用 Flanders 互动分析系统和 Community of Inquiry 框架，研究对象包含师生互动、学生互动和社会临场感。

论文结论支持多智能体课堂的互动价值。这份证据覆盖两门课程和特定实验设置。实验场景与真实学校保留距离。OpenMAIC 的仓库版本加入了课程生成、编辑、导出、持久化和模型供应商适配。论文证据与产品能力属于两张表。

这块需要注意一下。

演示效果抓人。教育效果需要长期数据。角色声音制造陪伴感。可靠教学系统需要判断误解、控制难度、校准反馈、保护学生数据。生成速度解决内容供给，学习科学决定知识吸收。

我觉得，这里藏着教育 AI 的第一条生死线。

课程生产失去稀缺性。

传统数字课程的生产环节包括教研、脚本、课件、录音、动画和题库。团队规模构成成本。生产周期构成壁垒。OpenMAIC 汇集这些环节，形成一条生成流水线。代码仓库提供 Vercel 与 Docker 部署方案。Node.js 22.19 和 pnpm 10 构成基础门槛。模型密钥构成运行门槛。

许多创业公司售卖课件生成、AI 配音或题库拼装。开源项目提供相邻能力。单点功能的报价空间收缩。

死刑二字夸张。降价通知四字准确。

第二条生死线属于课堂编排。

OpenMAIC 采用两阶段生成管线。课程大纲构成第一阶段，场景内容构成第二阶段。LangGraph 状态机管理角色发言和讨论。播放状态机管理课堂节奏。动作引擎管理语音、白板、聚光和激光笔等行为。

这个架构透露了一个产品判断。大模型问答构成一个零件。课程目标、场景顺序、角色关系和反馈规则组成系统价值。

教育公司的内容资产与课堂编排能力属于两种能力。模型公司的模型能力与教学法属于两种能力。OpenMAIC 显露两边的空白。

![OpenMAIC 互动场景，图片来源 OpenMAIC GitHub 仓库](/article-images/openmaic-ai-classroom/interactive.webp)

第三条生死线属于可验证结果。

项目页面列出 Python 入门、阿瓦隆桌游、股票分析和 DeepSeek 论文拆解等案例。这些案例证明场景跨度。案例无法证明学习迁移。

商业合同关心另一组问题。学生掌握了什么，教师节省了多少备课工时，错误知识造成多少损失，学校的数据去了哪里，课程记录支持什么审计。

爽文答案缺席。

GitHub 仓库本身给出了一份风险提示。v1.0.1 发布说明披露四份安全公告，问题涉及课堂存储路径、幻灯片 HTML 清洗、外部 URL 防护和重定向校验。团队修复了问题，版本发布日期是 9 月 6 日。

安全修复增加了项目的可信度。教育系统处理文档、语音、视频、模型密钥和学习记录。攻击面保留。安全公告代表工程团队承认真实世界的麻烦。

仓库记录 261 个开放事项。部分问题涉及 Windows 文件路径、Docker 权限、TTS 语言、模型超时和材料解析。35K 星标漂亮，261 个开放事项诚实。

产品长出肌肉，骨骼保持生长。

![OpenMAIC 项目制学习界面，图片来源 OpenMAIC GitHub 仓库](/article-images/openmaic-ai-classroom/pbl.webp)

那教育创业公司剩下什么？

我看到四类资产。

第一类是可信内容。医学、法律、工业安全和职业培训需要专家责任。通用生成器覆盖部分责任。

第二类是评价体系。好题目拥有独立价值。能力模型、错因分类和学习路径构成长期积累。

第三类是教师工作流。老师需要备课审批、班级管理、作业反馈和教务系统连接。课堂生成构成入口。

第四类是分发关系。学校采购、企业培训、证书体系和家长信任属于慢资产。这些资产需要长期关系。

OpenMAIC 跨越这个边界。v1.0.0 加入 Agent 工作台、持久会话、材料管理、二十个内置技能和课程修订。用户拒绝一次性结果。用户和 Agent 打磨整门课程。

这条路线像一位课程导演。导演接收素材，安排角色，调整节奏，重拍片段。教育软件的价值中心发生移动。内容库让位给生成系统，生成系统让位给学习闭环。

3.5 万星标刺痛行业。

清华团队开源了一所微型学校的生产线。AI 老师是其中一环。

生产线让课件变便宜。学校价值获得清晰轮廓。好老师理解学生，课程目标约束内容，评价数据修正教学，组织责任守住边界。

教育公司的危险并非 AI 老师抢走讲台。

危险来自另一件事。公司售卖一张课件。用户期待一间课堂。

一张课件的时代，产品比拼内容数量。

一间 AI 课堂的时代，产品比拼学习结果。

OpenMAIC 画出这条生死线。
