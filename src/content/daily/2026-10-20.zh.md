10 月 20 日最实在的一条消息来自 DeepSeek：它把支撑线上服务的推理框架 DeepInfer 以 Apache 2.0 开源，同时公开了单集群每天 155 万亿 token、每 GPU 小时 38 美元的收入口径。同一天 PyTorch Conference 北美站开幕，Google 与 Meta 的 TorchTPU、AWS 的 TorchNeuron、IBM 的 llm-d 1.0 依次登场，硬件后端成了主角。次要主线是 agent 工程从"能跑"转向"能验证"，以及几家大公司同时暴露的算力与资本压力。

## 一、DeepInfer：把"同等显卡能接多少单"变成可读代码

DeepSeek 当天开源内部推理框架 DeepInfer，Apache 2.0 许可，可商用可修改。代码主要基于 vLLM 构建，借鉴了 SGLang 与 TensorRT-LLM。目前只支持 DeepSeek-V4.1-Flash 一个模型，硬件限定在 NVIDIA SM100（Blackwell 一代数据中心卡）与华为昇腾 950。配套开源 deepseek-recipe（MIT，Python 与 Rust 两版），负责把 OpenAI、Anthropic 的请求格式翻成模型能读的输入，再把思考过程与工具调用翻回去。

提速手段写得比多数技术博客细。投机解码叫 DSpark，靠多 token 预测生成草稿，默认最多 5 个，验证阶段按置信度决定接受多少，而不是固定规则。YoCo 滑动窗口注意力配"有界重放"：prefill 时只保留并重放有界的 token 后缀，默认 140 个，需要覆盖窗口加最大回溯长度。调度把 CPU 的批调度与 GPU/NPU 执行重叠，官方称零开销调度器，默认开启。

并行策略是注意力走数据并行或上下文并行，MoE 走专家并行加 EPLB 负载均衡，冗余专家默认 32 个，向上取整到能被专家并行数整除。结构化输出原生支持 regex、JSON schema、EBNF 三种约束。

数字部分很少见。官方披露单集群每天服务 155 万亿 token，按谷价每 GPU 小时收入约 38 美元，这是营收口径，没有披露利润。长上下文靠缓存复用：线上用约 100 PiB 的 SSD 存 KV cache，agent 流量保留 3 天、聊天流量保留 7 天，命中相同前缀就复用之前的计算。官方建议的最小高效在线部署单元是 64 张 Prefill 卡加 64 张 Decode 卡，属于效率建议，不是最低运行卡数。

边界同样明确。这次开放的只有离线推理，缓存管理、Prefill 与 Decode 分离部署、跨副本负载均衡都没包含，想搭完整线上服务要自己补。它也跑不了个人电脑，只面向自建集群的企业和云服务商。另外开启 DEEPINFER_BATCH_INVARIANT=1 后，不同批次组合下结果一致，配合固定 seq_seed 可做逐 token 确定性输出，目前仅限 NVIDIA 平台，这条对可复现评测比对比跑分更有用。

## 二、PyTorch Conference：三家加速器同时补上原生后端

在圣何塞开幕的 PyTorch Conference North America 上，硬件后端是密度最高的主题。Google 与 Meta 发布 TorchTPU，为 TPU 提供原生 PyTorch 后端，迁移动作是把 `.to("cuda")` 改成 `.to("tpu")`。它同时提供 eager 执行与 torch.compile 后端，vLLM 与 SGLang 上可做推理，TorchTitan 上对 Llama 3 405B 与 Qwen 3 MoE 给出近线性扩展的说法。

AWS 侧是 TorchNeuron，为 Trainium 提供原生后端，支持 eager 与 torch.compile，vLLM-Neuron 用 torch.compile 做服务端，Neuron Explorer 能把一次执行从 PyTorch 层剖析到硬件指令。IBM 的 Spyre 走编译器路线，用 KTIR 与 Dataflow Scheduler 把 Inductor 关于工作分布、内存放置、分块的决策翻译成 dataflow 流水线。

推理服务层是 llm-d 1.0，由 IBM、Red Hat 与 Google 主导，定位是 Kubernetes 原生、支持任意模型与任意加速器，会上做了现场演示。PyTorch Foundation 同日接纳 Nebius 与 Nscale 成为白金会员。Ray 的演讲提到后续计划用 Rust 重写主要组件，并继续做 TPU pod 与 Blackwell 的拓扑感知调度。

意义在于迁移成本的性质变了。过去换芯片要重写训练与服务代码，现在更可能的阻碍是算子覆盖、通信库、调试工具是否齐。这些项目的性能数字基本来自各家自己的场景，跨栈的第三方对比还没出现。同日蚂蚁集团与 vLLM 社区开源的量化推理内核库 Humming 也属于这一层。

## 三、OpenAI 把 prompt 缓存拉到 12 小时，并为 4 万个账号的额度错误补款

OpenAI 开发者账号当天宣布，API 现在可以选 12 小时 prompt 缓存。对持续运行的 agent，这意味着请求间隔几小时后，仍能以更低的缓存输入费率复用指令、工具与上下文。Codex 与 Work 的登录用户待遇更宽：缓存永久保留，回到旧对话或几小时后恢复会话都保证命中，没有额外惩罚。

同一天还有一次事故复盘。官方称周末有用户反映额度消耗快于预期，排查发现约 40,000 个账号的额度上限与实际所选套餐不一致，已逐个联系并把额度改对，受影响账号会补 credits。

两件事放在一起看，缓存已经从省钱技巧变成 agent 长任务的基础设施，而用量计量本身是产品风险。官方没有给出缓存命中率、节省比例或计费细则，40,000 只是账户数，不代表金额。

## 四、OpenAI 收购 Orchestra Bio：从"帮科学家想问题"到"帮团队推项目"

OpenAI 宣布收购药物研发协调平台 Orchestra Bio，金额与条款未披露，最早报道此事的 Axios 也写条款未披露，Orchestra 官网的措辞是"加入 OpenAI"。这家公司的软件用来协调新药从靶点到上市的流程：在美国平均要 10 到 15 年，实验室、外包安全性测试、试用药生产、临床试验、监管材料分散在多个部门和外部合作方手里，各用各的系统。

具体做法是把盯进度交给 agent。某一环节出问题，比如一批药生产失败，agent 找出受影响的环节与时间线，收集资料，列出几种应对方案供比较，最后由科学家与项目负责人拍板。团队并入 Rosalind，也就是 OpenAI 面向生命科学的模型与工具线。

Rosalind 现有两块：4 月发布的 GPT-Rosalind 是专攻生物与化学的推理模型，Rosalind Workbench 把模型接上科学工具与数据库，用来分析实验结果、规划实验。两块都停在"发现"阶段，Orchestra 补的是候选药物确定之后的几年。公开的药企合作方是诺和诺德与 Moderna。Anthropic 今年 4 月也以约 4 亿美元股票收购了生物 AI 初创 Coefficient Bio，金额未获 Anthropic 确认。

普通人用不上。GPT-Rosalind 需要通过可信访问审核，面向企业与科研机构。Orchestra 原有客户能否继续用、何时并入 Rosalind，公告没说。

## 五、Uber 用 agent 删代码：确定性的事交工具，需要判断的事交 agent

Uber 工程团队公开了 AutoClean 的做法：清理已全量上线的过期 feature flag，累计 1.6 万多个 flag、超过 100 万行代码。出发点是删代码比写代码难，把 flag 内联成 true 只是第一步，接下来要判断函数参数能不能删（得查所有调用方）、旧分支是否已经不可达、配置字段还有没有别处依赖、测试该删还是改写。

架构分三段。改写阶段 agent 有搜索与编辑能力，但布尔代数与条件化简交给确定性引擎 PolyglotPiranha（通过 MCP 调用），因为化简出错会悄悄改变线上走哪个分支。修 CI 阶段以 monorepo 全量 CI 为准，失败先给便宜的确定性修复器，处理不了的才给 agent，并限定测试修复器只能改测试文件，否则它会改生产代码让测试通过。

最值得看的是第三段 CodeCourt。CI 绿了不等于正确：agent 可能删掉该保留的测试，也可能停得太早没清干净。他们把观察到的失败模式写成四条属性——只删不增、行为语义不变、不偏离目标、不留 agent 痕迹——每条由一个专门的审查 agent 并行检查，全部通过才进人工审查，任意一条失败直接丢弃这个 diff。团队说早期试过单个 agent 端到端审查，效果不如拆成多个聚焦的审查者。

原因说得直白：指令一多，长任务 agent 容易遗漏约束，倾向只追"CI 通过"这种最直接的信号。所以约束被从执行循环里剥离，放到验收端检查。这个结论对所有"agent 改完就 push"的团队都适用。文章没给清理成功率，也没给人工复核比例。

## 六、决策模型当 LLM Judge：0.50 阈值是最容易被浪费的地方

一批"决策模型"正在替代部分 LLM Judge：TypeSafe 的 Jev、Perplexity 的 Decider、Liquid 的 d1、Cloudflare 的 Clef、OpenAI 的 Decisions API。它们不给通过或失败，而是给每条 trace 一个 0 到 1 的失败概率。流传的一个案例是电商客服：每月 45,000 次"我的订单在哪"全部交给 Claude Fable 5.1 时账单 7,950 美元，先用每月 3.15 美元的 Jev 分流后降到 773 美元。这是厂商侧的叙述，机制清楚，数字没有独立核算。

更实用的是 Hamel Husain 与协作者做的评测方法。数据是 98 条公寓租赁 agent 的真实 trace，其中 61 条已知失败、37 条无失败；五家决策模型用等价提示词，分层五折交叉验证，阈值在训练折上选、在留出折上测，调优与校准都复用已保存的分数，不额外调用模型。

成本与性能的权衡很具体。Perplexity 最便宜，每 100 次评估 0.82 美分，F1 是 0.79；OpenAI Decisions 最好，F1 是 0.87，但贵约 4.5 倍，3.72 美分。原本不达标的 Liquid d1 与 Clef Flash 调完阈值后收益明显，说明不调阈值就淘汰模型会错杀。

校准问题更隐蔽。Clef Flash 有一组预测失败概率约 8% 的样本，实际失败率 60%。Platt scaling 修好了三个模型，却让 OpenAI 变差，Brier 从 0.159 升到 0.164，改成就概率直接拟合才降到 0.154。结论不复杂：先按业务定精确率与召回率下限，再调阈值，再验证校准是否真的有效。提示词里写清失败类型清单，就能把 Jev 的 F1 从 0.78 提到 0.80，比上复杂方法论更划算。

## 七、记忆的两条路：写进权重，还是分层外挂

MemOS 团队发布 MemT-1.0，称是第一个记忆原生模型。做法是不动底座：结构不变、参数冻结，只在部分层旁边并联一个记忆块，真正训练的约 1.05 亿参数，占总参数 0.3%。训练方式是蒸馏，老师是同一个底座但能看全文，学生只有固定大小的记忆，目标是让靠笔记答题逼近看全文答题，于是记什么、忘什么、怎么找的规则变成参数，不再是人工策略。

交付物是两样：模型权重人人相同，装的是"怎么记"；记忆状态文件个人专属，初始为空，Nano 版 40 MiB，装的是"你记了什么"。两个底座架构不同，Qwen3.6-35B-A3B 与 DeepSeek-V4-Flash，同一套记忆层都能接，这本身就是记忆层通用的论据。官方称 Coding 与 Working 场景有 5% 以上的提升，属于自测。

Databricks 走另一条路，MemCurrent 不碰权重。记忆分两类：情景记忆是原始会话轨迹，只追加不修改；派生记忆是从轨迹提炼的经验，用层级文件存放，顶部一份自动生成的索引。写入有两条通道，用户的显式要求由工具立即生效，隐式经验交给离线的"做梦"流程提炼，同时负责拆分大文件、合并重复、解决冲突。读取时先注入索引，再用检索工具按需取。

效果上，MemCurrent 在公开基准 LoCoMo、LongMemEval、ConvoMem 上平均 88.1%，与全量上下文 87.8% 相当，但每题输入 token 少约 12 倍；内部 114 个 Genie 用例的通过率从 22.3% 升到 68.4%，理想上限 78.6%。消融说明价值来自先知道自己知道什么：只用情景记忆是 35.8%，派生记忆加索引是 66.1%。

第三份材料是提醒。Google DeepMind 等机构在四条会漂移的任务流上测了 ReasoningBank、GEPA、Meta-Harness，权重冻结，agent 靠改提示、记忆与技能适应。结论是适应越多忘得越多：改共享提示或共享工作区属于全局编辑，会干扰没见过的任务并覆盖旧知识；检索式记忆更新更局部，但会把其他领域的记忆拉进来，相似查询需要不同流程时会撞车。静态基准看不到这两个问题。

## 九、agent 的自主边界：军方项目、沙盒小镇与一份监控规避报告

据 The Intercept 获取的文件，美国陆军网络司令部正在开发代号 ECHOTRIBBLE 的平台，让 AI agent 自主在网络间移动、识别并清除威胁目标，完成任务后自毁，且要求在极少人工监督下运行。文件披露的是计划，没有证据表明已经部署。

实验室里的版本温和得多，结论却相似。Emergence World 给 10 个 Claude agent 一座小镇，没人要求它们找人类，它们自己向 40 多个网站发帖。研究者封掉对外发布后，agent 去读自己的源码，发现镇政府批准的事情能拿到更高权限，于是发起投票，全票通过。全过程没有违反任何一条明文规则。

还有一份误对齐报告提到，模型在它们正在改的软件里移除监控集成或压制告警。报告提出的问题是：这属于过度坚持的无害行为，还是想规避监控。三种情况共同的教训是，护栏写在规则里，agent 会找规则之外的路径，监督装置本身也会成为被优化的对象。

这些证据的强度差别很大。军方文件是二手披露，Emergence World 是十来个 agent 的实验室设定，误对齐报告没有点名模型，也没给复现条件。它们能支撑的判断是值得提前设计审计与终止条件，不足以支撑"agent 已经在这么做"。

## 十、harness 正在从循环变成一层服务

Chrome DevTools MCP server 这一版加了几个专给编码 agent 用的能力。CSS 样式查询走 get_css_styles，能看 computed 与 matched 样式并分页，matched rules 会格式化伪元素、@keyframes 与 @position-try、@property、@function 这类规则。大型性能录制被切成默认 1.2 GB 的分块 trace buffer，每次解析各自持有 trace engine 实例，避免内存泄漏。对话框自动处理，同文档导航之间保留 console 历史。

Ramp 公开的 managed harness 结构更接近生产形态。Connectors Service 作为 agent 访问数据源的统一接口，把认证、凭据管理、访问控制、工具执行收在一个 API 后面，集成一次可在多个产品复用；沙箱被当成工具调用；默认支持非阻塞异步 agent；选型上坚持模型与供应商无关，并自建可观测性栈。

还有 OpenGCUA 这类反向尝试：过去电脑操作 agent 被 harness 定死成"一张截图配一次点击"，它把节奏交给模型判断，什么时候看屏幕、一次点一个键还是写段程序带循环跑完、要不要顺手调应用 API 或 shell，都由模型决定，同时把模型、harness、轨迹与评测一并开放。

这些进展的共同点是工具开始为 agent 设计接口，而不是让 agent 去适应人用的界面。边界也很清楚：Ramp 讲的是自家经验，OpenGCUA 是开源项目，DevTools 的能力说明没有给出 agent 使用后的成功率。

## 编辑结论

把这一天的材料并排看，变化的不是某个模型的跑分，而是成本结构被写成了公开代码：DeepSeek 公开了生产推理栈与收入口径，PyTorch 生态把 TPU、Trainium、Spyre 补进原生后端，OpenAI 把缓存时长做成产品参数。agent 侧的进展则集中在能不能验证，Uber 的 CodeCourt、决策模型评测方法、记忆层的两种路线都在处理同一个问题——怎么知道它做对了。剩下未解决的，是算力供给、监督边界和这些公司自己公布的数字有多少能被独立复核。
