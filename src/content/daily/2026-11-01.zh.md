11 月 1 日是周日，几家主要厂商博客都没有新发布。当天有信息量的是从业者在会议和社群里披露的流程细节：编码 agent 已经把"写代码"变便宜，卡住交付的是验证、审查和合并。Anthropic 的日合并量据其工程师口径从 5 月的 2500 次升到约 3 万次。同期出现的新工具开始把"可复现证据"做成提交前的硬门槛，而架构侧的讨论转向怎么分配人的注意力。

## 主题一：日合并量涨了十二倍，人审的对象换成了证据包

Addy Osmani 和 Manish Kapmani 在一场工程会议上的分享被整理传播。按 Addy 的说法，Anthropic 的日合并量大约从五月的 2500 次提升到约 3 万次，Claude 承担首轮审查。关键变化不在模型多强，而在提 PR 时必须附带证据：端到端测试、浏览器实跑、lint、截图或录屏。

现场举手调查显示，几乎所有人都让 agent 开过 PR，但真正逐行读完再合并的极少。Manish 的补充是 CI 侧承压明显，约三成合并尝试仍然失败。他把这套东西叫软件产线，并区分"亮灯工厂"和"黑灯工厂"：前者人还在规划、构建、检查、发布里用判断，后者人只定意图和处理大例外。多数团队处在两者之间，2027 年底之前不太可能整体熄灯。

可操作的部分是几条约束。把团队约定写进 AGENTS.md 或 CLAUDE.md 这类文件；用 hooks 盯住编辑和 diff，尽早修；把"验证"拆成具体测法，端到端、属性测试、视觉比对各管一段。Addy 强调只说 verify 太空。另有人按爆炸半径给变更加绿黄红，支付类路径不放开自动合并。

同场还有另一层意见，争论点是谁来做验证。SonarSource 一方主张零信任，agent 环、CI 环、维护环各配独立验证：确定性层抓注入、溢出这类已知模式，agent 审查抓逻辑与意图，供应链层看 CVE 和恶意包。企业侧还要管 agent 身份、遥测、权限和沙箱，他们更愿意用"导轨"这个说法，把 agent 限制在批准过的路径上，而不是事后拦截。

责任归属没有跟着自动化转移。分享里的原话是写得快不等于发得快，自主权是挣来的；你让 Claude 跑完，出事还是你修。有人为铺验证流程停掉新产品约六周，事后认为值得。留给初级工程师的功课不是学更多工具，而是弄清"验证"在自己产品里到底对应哪些测试。

证据边界：这些数字来自讲者的公开分享，不是 Anthropic 的官方统计。合并量上升与回滚下降的对应关系也由讲者口述，没有可核查的时间序列。它能说明方向，不能当作行业基准。

## 主题二：OpenRouter 用 233 行脚本把"可复现"做成门槛

OpenRouter 公开了一份只依赖标准库的 Python 审查脚本，233 行，把 AI 代码审查从"读 diff 提意见"改成"在沙箱里跑一遍"。流程是四件工具拼起来：Files API 上传变更后的全文和上下文，避免只看 hunk 猜 import；shell 把文件拷进托管容器，可以跑 Python 和 SQLite；apply_patch 提修复补丁，平台先校验 diff 语法；最后用严格 JSON 收尾。

每条发现必须标成 confirmed 或 unconfirmed。confirmed 要附命令和输出。演示里埋了 SQL 注入、分页 off-by-one、`is not` 比字符串、retry 吞异常、去掉 conn.close() 五个 bug，原有单元测试全绿。Haiku 跑了四条 confirmed，连接未关那条标 unconfirmed，因为 CPython 出作用域会自动关，难以稳定复现。

代价是明确的。三次复跑里 Haiku 5.5 平均约 0.0153 美元、125 秒，召回高但补丁只有一跑修全五个；Sonnet 5.5 约 0.0447 美元、60 秒，五个全中且三次补丁都过自测。沙箱另计每秒 0.0001 美元，所以模型想得久也会多花钱。整体比"只塞 diff"的调用贵 10 到 40 倍，换来的是可重放的证据。

限制也写在文档里：代码会上传给模型提供商，单次最多约 20 个文件，沙箱默认无外网，工具仍是 beta 且只有全球端点。报告默认写进 .git/ai-review.json，避免误提交。--apply 之前仍建议人工看补丁，Haiku 曾把字典访问改成元组下标。

## 主题三：编排层成了一个岗位，但它不该自己写代码

Rob 根据 Lauren Tan 和 Theo 的实际用法整理出一套分工：编排 bot 管第一公里和最后一公里，也就是收齐意图、追进度、验收；写代码交给有独立机器的 Claude Code、Cursor 或 Codex。核心主张是别堆几十个 bot，用一个"chief"统筹委派。

Lauren 的日常环是这样的：盯产品相关 Slack，开 Linear 单，由 Cursor 云 agent 在独立机器上复现，然后开一个 fix and fuzz 的 PR，让一小群 agent 用随机点击和 Playwright 试着打破修复。fuzz 干净后 Slack 通知，约一小时无异议就自动合并。她月级 PR 上千。有人不爱"工厂"这个比喻，她更愿意叫米其林厨房：你是主厨，菜是团队做的，盘子上仍是你的名字。

支撑这套流程的是一个倒金字塔。底层是代码库边界和强类型，让"容易做的事就是对的事"；往上是静态分析、lint、测试和 CI，同一个错反复人工收拾就写成确定性规则；再往上是 AGENTS.md、skills 和各种 bot；最顶上才是人审，最贵、最不该扩规模。

有两个风险值得记住。安全上，多个 Grok Bot 共享一台云电脑，文件、浏览器会话和 CLI 凭证都在里面，一个 API key 登录后别的 bot 也可能用到。流程上，作者自己的经验是越自主越不能指望 agent 自律，控制要放在环境里：沙箱、最小权限、允许开 PR 但默认不合。

他落地时还踩过几个坑。别真的去造五十个 bot，用一个 chief 统筹委派就够了；权限收到最窄；凭证放进 vault。backlog 进 Notion，用 RICE 加爆炸半径打分排序，可以主动建议改进，但不要为了填满 backlog 而刷任务。Lauren 那边用 routine 从 Slack 的 bug 报告和 X 上的抱怨里收上下文，前提是推理额度足够高，否则高频调用扛不住。

## 主题四：Super-agent 六层里只有两层用模型

DeepSeek Harness 团队发布了 Super-agent 的设计文章，并开源了原型项目。它要解决的问题是单会话智能体难以跨任务协作，人得反复切换窗口。方案是 Router 统一沟通调度，Worker 并行执行，靠事件驱动和故障恢复让智能体跨聊天和代码托管平台持续工作。

一位读者的逐层拆解值得看。接入层对接代码平台和即时通讯，前者定时轮询，后者实时订阅，断线后补齐历史消息，所有外部消息统一成触发事件并归入会话线程。准入层用纯规则引擎决定一条消息能不能变成任务，判断依据只有三个：发送者是否在授权名单、是否点名了智能体、该渠道的准入策略。这一层完全不经过模型。

研判与编排层才交给模型：一个长期在线的会话只做判断和分派，看与本项目是否相关、是否确实有人想做、方向是否明确，然后选择新建任务、并入已有任务或只做答复。任务层给每件事一张工单，任意时刻只处于一个阶段，比如等交付确认、等回答、等评审、受阻、排队、执行中。

执行层给每张工单分配独立会话和独立分支，工单之间完全隔离才能并行。交付层把所有对外消息收进统一队列，原路送回最初那段对话，只有在受理、交付、需要人决策、执行受阻四种情况下才触达人。所有对外动作都先写持久化存储再执行，思路接近预写日志，崩溃后可重放。

证据边界：目前只有团队的设计文章、开源原型和两位读者的解读，没有第三方压力测试，也没有真实团队的使用数据。一位做过协作 agent 的读者提醒，规模上去后最难的是克制：不能大家都在群里和 agent 聊个不停，内部几十个动作要收敛成人能看的几条。分层是否成立，要看它在消息量大、意图模糊时还能不能守住"只打扰几次"的承诺。

## 主题五：Karpathy 两小时做出 HackerTube，手动部分只有三件事

Karpathy 周末花了约两小时，让 Claude 把 Hacker News 二十年的 4300 万条评论筛成 6454 个反复被推荐的视频，做成一个不用登录的视频站。他自己的评价是观看体验比 YouTube 推荐好得多。

过程细节比结果更有意思。他默认用 Claude Code 的 Mac 桌面版配 Opus 5.5 中档推理，全程只跟 Claude 说话。真正需要他动手的只有三件：在 Google Cloud 界面建一个查视频元数据的 API key、开一台 VPS、买个域名。之后把 IP 交给 Claude，让它更新、加固、部署和优化，剩下全由模型完成。

几个设计选择也跟着出来：状态存在本地浏览器会话；缩略图取视频中段的一帧，而不是上传者做过 A/B 优化的封面；评论分析数据打包成一个压缩包，别人可以拿去让 Claude 生成自己的版本。当天就有人照做，从 HN 帖子里抽出 1.5 万多本书，只保留至少被两人提到过的，做出 HackerBooks。

证据边界：这是个人周末项目，能证明建站成本下降，不能推出团队产能提升。他自己也说这类项目过去要几周甚至几个月。另有观察者注意到他日常用的是中档推理强度，这比"用了哪个模型"更影响成本。

## 主题六：428B 模型开始往本地搬，靠的是量化生态而不是新模型

MiniMax 官方发帖谈 M3.1 Flash 的本地化，重点不在模型本身，而在把 428B 参数压进消费级硬件的社区工作。帖子里逐个致谢了八组贡献：Unsloth 的 2-bit Dynamic GGUF 权重做到 143.9 GB，并做了编码、工具调用等负载的校准与保真测试；SAGE-EXL3 给出 token 级保真度和单台 DGX Spark 的配方；有人用 4 张 RTX 3090 结合专家缓存和系统内存；MLX 社区在 Apple Silicon 上做 oQ 量化和解码；AMD 的 Quark MXFP4 适配了 Instinct。

技术上的取舍被讲得比较清楚。低位权重同时降低加载模型所需的内存和解码时搬运的权重数据，但要真拿到收益，需要仔细校准、高效的低位 kernel，以及把专家合理分配到 GPU 和系统内存。三者缺一，省下的显存会被更慢的解码吃掉。

这条线值得留意的地方在于，它把"能不能本地跑"变成工程量问题而不是模型能力问题。同一周还有社区的 Pika-H3-Flex-Turbo-LoRA 把视频生成速度做到官方版 2.4 倍，代价是 2 步和 4 步版本只融入了约一半风格强度。

证据边界：MiniMax 这条是厂商致谢帖，列的是社区成果，没有官方统一的速度和质量对比；第三方量化在不同硬件上的表现差异会很大，143.9 GB 仍然是多卡或多机级别的占用。

## 高价值单点

- **卡兹克的四层 agent 自动化**：他用一年搭出事件中台、Agent 执行、CI 中台和飞书决策四层。rules.json 统一管理事件触发与调度，本地 MacMini 跑任务，自建 CI 完成审查、检查、合并、发布、核实五步，只在删数据、花钱、改方向时通过飞书卡片找他拍板。他此前是设计师，产品已开源并拿到约 9000 star。
- **unslop 这个 skill**：在 Claude Code 里触发后，先审计现有界面里的紫色渐变、发光文字、emoji 标签、"New ✨"、大写宽字距和不均匀间距，逐条列出位置，再定一个设计方向。只改视觉，功能、文案、区块顺序不动。
- **global-law 把法律条文放进 git**：每次法律生效算一次提交，可以查某一天的条文、对比两天差异、追到每个词是哪部法律改的。已有德国基本法自 1949 年起的记录，附带 18 个只读工具，接给 AI 后可回答"这条规定某天怎么写"，且在本机读仓库、不需联网。
- **OpenBot 的许可争议**：这款桌面应用先用 PolyForm Noncommercial 许可，开发者说过商用随便用，几天后推出商用收费套餐。按开源促进会的标准它不算开源，更准确的说法是源码可见。争论中有人找出 Open Duet 和 OpenMausBot 作为平替。
- **Alma 把远程连接换成二进制帧**：端到端加密通道改用二进制帧后流量减少 25%，iOS 上加解密与编解码快约 80 倍，1 MiB 数据从 66 毫秒降到 0.8 毫秒，旧版本自动回退，不需要两端同时升级。
- **Vercel agent-desktop 绕开截图**：它读取操作系统的无障碍树，返回带 refs 的 JSON 快照，agent 用 ref 操作后重新读取验证。相比截图加视觉识别更省 token 也更快，但准确度还没有公开测试结果。
- **对 personal agent 需求侧的质疑**：一位从业者提出，用户不需要 AI 健康管家，只想少生病；一个月省半小时却要花一小时配置和检查的助理，经济价值不足。他的判断是 personal agent 最大的竞争对手是用户什么都不做。
- **斯坦福 CS329A 全课上线**：Self-Improving AI Agents 九节课已收录到 YouTube，课程目标是造一个能自我改进的智能体，骨架是一线经验加论文精读。

## 编辑结论

周日的厂商博客是空的，能读的是流程。当天几条独立线索指向同一件事：写代码不再是稀缺环节，稀缺的是敢合并的证据和能持续供给的注意力。OpenRouter 的审查脚本和 Anthropic 的合并量是两个尺度的同一答案——把判断写进可执行的检查里。Super-agent 的六层架构则回答另一个问题：当一个系统每天产生几十个动作时，怎么让人只看到该看的那几条。
