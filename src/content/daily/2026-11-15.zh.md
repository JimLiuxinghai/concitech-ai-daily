## 主题一：黄仁勋离任一周，回归传闻与未结调查同时存在

据 AI Valley 与 The Verge 播客转述，黄仁勋于 11 月 12 日辞去英伟达 CEO 与董事职务，即时生效，CFO Colette Kress 出任临时 CEO。消息公布当天股价盘中跌超 13%，收盘跌约 4%，次日回升。现有材料里没有公司公告原文，也没有继任安排的细节。

11 月 15 日，《金融时报》援引多名知情人士报道，黄仁勋已与几位亲信讨论过重新出任 CEO 的可能；一名盟友称正召集硅谷高管组成"作战室"，游说董事会并争取白宫支持。报道没有公开这位盟友的身份。

公开信"Stand with Jensen"要求董事会先让他回来、等独立调查查清事实，并公开调查范围与时间表。据 Moneywise 11 月 14 日统计，签名超过 10 万，其中 5000 多人自称英伟达在职员工；11 月 15 日另一条帖子给出的数字是约 15 万签名、7000 多名员工。两组数字口径不同，且都来自转述。

辞职的背景说法集中在个人关系，以及围绕新加坡云服务商 Megaspeed 的出口管制调查。相关报道与议员表态已经出现，但材料中没有公司调查结论或司法认定。11 月 17 日（周二）英伟达发布财报，这是临时 CEO 任内第一次公开交代。

## 主题二：Qwen4-Max 用 2.4T 骨干与百万上下文拿下 Agent Arena 中国首位

Qwen 团队发布 Qwen4-Max，基于新的 Qwen4 架构，拥有 2.4T 骨干参数、每 token 激活 71B、328B N-gram Embedding 参数，原生支持视觉，上下文窗口为 100 万 token。官方博客同时给出架构细节、成本对比和行业实测案例。

同一天，Arena 的榜单账号称 Qwen4-Max 以 +7.5% 的净提升在 Agent Arena 排到第 14 位，成为排名最高的中国模型，使 Alibaba 成为排名第一的中国实验室、总榜第 5，仅次于 Anthropic、Google、OpenAI 和 Meta。该排名基于 1.47 万条真实 Agent 会话，并附四项信号拆解。

参数规模与上下文长度已经是国产模型发布时的常规叙事，这次值得记下的是评价维度换了：不再是单轮问答榜单，而是多轮、带工具调用的 Agent 会话。这也意味着分数更依赖具体任务分布，跨榜单比较的价值有限。

两处信息都来自发布方与榜单方，材料里没有第三方复现。2.4T 参数的实际推理成本、百万上下文在长任务中的有效召回率，都还没有独立数据。

## 主题五：Claude Code 的 Code Mode 把工具调用改成一段 JavaScript

Claude Code 推出实验功能 Code Mode，默认关闭。开启后模型不再一次调一个 Bash、Read 或 Edit，而是先写一段 JavaScript，在一次执行里调用多个工具，由 Claude Code 在本地会话中运行。官方举的例子是把重试上限从 3 改成 5：先用 rg 找文件，再改参数，接着跑测试，最后只把文件路径和测试输出交回上下文。

收益来自三处：独立命令可以并行；上一步结果能直接传给下一步，不经过模型；中间产生的大量输出可以先在代码里筛，只把需要的部分放进上下文。官方推荐的使用场景也集中在这三点——同一处改动要改很多文件、搜索结果需要先过滤、几个独立命令可以同时跑。

限制比收益更能说明它的定位。它只能在终端交互式会话里用，不支持 `-p`、Agent SDK、VS Code 面板、桌面端与云端会话；不能走网关、Bedrock、Google Cloud 或 Microsoft Foundry；只支持 Opus 5.5、Sonnet 5.5、Haiku 5.5 和 Fable 5.2。前台最长运行 10 分钟，后台最长 2 小时且要求会话以 auto 或 bypassPermissions 模式启动。

开启方式是设置 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`，写在项目设置文件里不生效，因此克隆下来的仓库没法替使用者偷偷打开；首次开启需要确认。权限模型的变化值得单独记住：每次工具调用仍要过 deny、ask 规则和 PreToolUse hook，但 auto 模式的分类器现在审的是整段代码，看不到运行时才算出来的值，比如从搜索结果里取到的路径。官方建议，必须管住的调用要靠规则或 hook 兜底。

## 主题六：常在线 Agent 被写成一份参考架构

Anthropic 发布《Building always-on agents》，把"始终在线"拆成五个部件：事件收件箱（所有触发源写入一个持久化队列）、定时器（独立存储的 follow-up 与 schedule）、记忆（独立于会话的持久存储）、权限、出口。循环是：事件进收件箱，worker 启动一次 run 并新建或恢复会话，Agent 加载记忆、在权限内行动、更新记忆，结果进出口，dispatcher 投递；定时器或用户回复再把事件送回收件箱。

这个设计的核心判断是：始终在线是一种使用体验，不是一直开机。每次 run 都很短，大部分时间在休眠，靠持久状态把多次运行拼成连续体验。文中也把中断后如何恢复、哪些动作可自主执行、何时该告诉用户列为同等重要的问题。

社区已经在对齐实现。一条帖子用 Pi Durable 与 Pi AI SDK 组装同类架构：Conversation 保存讨论，Submission 接收输入并用稳定的 requestId 关联重复请求，Harness 调度生成与工具任务，Durable Storage 保存历史、检查点和结果，进程重启后重新打开存储恢复。作者强调外部操作还需要幂等或结果核对。

这类文档的价值在于把"Agent 项目经理"的直觉写成可实现的组件边界。它也顺带解释了当下产品形态的差异：能连续工作几小时的助手，和能记住三天前约定的助手，工程上不是同一件事。

## 主题七：Poppy 1.0 让企业给 Agent 开一道正门

据 Sierra 协议发布转述，Poppy 1.0 让企业通过域名下的发现文件，公布自己的网站、API 或企业 Agent 入口，并衔接身份说明与登录授权。它解决的是 Agent 代表用户访问企业服务时的身份问题：商家要能确认来者是替某个用户办事的个人 Agent，而不是匿名爬虫。

落地进展已经开始出现：据 Sierra 介绍，Shopify 平台店铺已自动发布 Poppy 文件，Meta Muse 也已启用该协议。商务扩展对接 UCP，具体购物流程由 UCP 承担。

一位开发者的实测更具体：Alma 0.4.672 支持自动发现公司的 `/.well-known/poppy.json`，访问 API、页面或 MCP server 时带上签名的 Poppy-Session 头；UCP 结账时带上 Alma 的 UCP 平台 profile，实测在 Allbirds 的 Shopify UCP 端点上协商出了 checkout、cart、order 等全部能力。

如果这套协议铺开，Agent 购物的瓶颈会从"能不能自动点完流程"转到"商家认不认这个身份"。现在的证据还只有协议方的转述和一个实现者的实测，缺少商家的独立说法。

## 主题八：同一模型的安全分能差 34 个百分点，专家异议还会改掉正确答案

Anthropic 公布的一组评测显示，Fable 5.1 在自杀与自我伤害的多轮评测中，API 配置下得分为 60%（±14%），采用新系统提示的网页端为 94%（±7%）。同一个模型，34 个百分点的差距来自部署方式，而不是权重。

团队据此主张按场景衡量"恰当回应率"，并在报告里同时给出系统提示、接口和评分配置；建议复杂多轮评测至少 100 个用例，简单单轮评测至少 1000 个。这套要求实际上是在说：安全分数脱离配置就没有可比性。

另一项研究从相反方向给出了同类警告。两阶段修订实验固定问题、证据与初始答案，比较中性反思、匿名异议和领域专家异议三种条件。五款模型在 1989 项医学、科学与法律判断中，都没有在专家异议条件下达到净提升准确率所需的选择性纠错门槛，准确率最多下降 16.1 个百分点。

值得注意的是分层结果：单独增加"专家"标签的准确率影响介于下降 5.2 点到上升 2.4 点之间，与整体异议效应必须分开看。也就是说，模型对权威的敏感和对论证的敏感是两件事，前者更容易被利用。

## 主题九：低精度训练、记忆压缩与内核优化三条降本路线

Thinking Machines Lab 以 Apache 2.0 开放 Inkling 2 Small，5940 亿参数，从预训练到最终强化学习的前向计算都用四位精度。材料称预训练耗时减少 8%、强化学习耗时减少 20%；反向计算并未同样维持四位。显存门槛也写得很直白：NVFP4 至少需要 500GB，MXFP8 至少需要 800GB——名字里的 Small 不代表消费级单卡能跑。

斯坦福研究者发布的 Memorilla 走的是另一条路：把文档集合编码成固定的 16 个记忆词元，用来辅助冻结模型。在 FactKG 上，冻结的 Qwen3-8B 准确率达到 84.33%，全上下文对照为 80.43%，文档词元用量减少约 108 倍。它并非全面领先，在 PubMedQA 等基准上仍落后于对照；代码、训练方案和检查点以 Apache 2.0 开放。

CUDA-L2 论文第五版则把优化对象放在内核层：结合大模型与强化学习，以 CUDA 执行速度为奖励，自动优化 1000 种半精度矩阵乘法配置。在受测条件下，相比 cuBLASLt 的自动调优方案，离线模式平均提升 11.4%，模拟实时推理间隔的在线模式提升 15.9%。

三条路线分别对应显存、上下文和内核，共同点是都没有宣称通用加速。这些数字都限定在特定配置与基准下，不能外推成"训练成本降一成"这类结论。

- **多智能体委派没有稳定增益**：Lost in Delegation 按训练知识截止前后划分任务，发现委派未持续优于非委派；面对编排模型缺少的后截止知识，准确率可能明显下降，同一模型直接用工具反而更好。常见问题是查询失真、工具使用低效和跨智能体信息丢失。
