今天的两个主线彼此呼应。产品侧，Anthropic 把 Claude 对话里生成的工具做成了可以装进程序坞的应用，入口从浏览器标签页挪到了桌面。研究侧，一份黎曼猜想的形式化证明被压缩到 7.6 万行，Lean 内核和多套独立检查器都通过了，但还没有数学家完整读过。

其余信号分成三组：智能体安全研究集中给出了量化结果；额度与价格的账本在同一周被反复重算；SpaceX 的百万颗算力卫星拿到了监管许可。数学与理论物理领域本周冒出的一批"成果"，多数仍停在机器验证或社交转述阶段，这一点需要放在前面说清。

## 一、Claude 的应用现在能装进程序坞

Anthropic 正在测试 Install as app。用户在 Claude 里让它做出一个追踪器或小看板之后，可以直接点安装，产物变成 Mac 程序坞或 Windows 开始菜单里的独立图标。不用写代码，也不用配置，想改就回到对话里说一句，应用跟着更新。测试期内所有档位都能用，包括免费版。

有人把这个应用拆开看过：体积 404 KB，本质是两个小文件加一个图标，打开的是一个 Claude 内部的窗口。这解释了三件事——它不能离线用，必须保持登录，运行消耗仍然算进你的用量额度。同一个需求用两种方式提出，得到的成品也不一样：一种是能脱离 Claude 独立运行但从此不再变化的程序，一种是持续跟着对话变化但离开 Claude 就无法存在的壳。

真正需要谨慎的是权限。这类应用可以申请整台电脑的访问权，也就是执行程序、读取修改乃至删除文件。这个权限只能授予自己做的应用，Claude 会在每次更新后重新确认。但 Anthropic 不审核这些应用，而且事后收回权限并不能撤销已经发生的操作。别人的应用清单再热闹，也不该照着装。

这个功能改变的不是开发方式，而是小工具的分发门槛。此前一个人想要"下午四点订单还没发出就提醒我"这种需求，要么自己写，要么等某个开发者觉得值得做。现在提一句就能得到一个带图标的程序，成本几乎为零。社区里已经出现的射击游戏、地理测验、Mac 清理工具只是玩票，真正会积累起来的是那些没有商业价值、但对具体某个人有意义的工具。代价是这些工具都依赖订阅和网络，一旦停止付费或 Anthropic 调整功能，它们不会变成遗产。

## 二、黎曼猜想的证明被压到 7.6 万行

Anthropic 的研究人员与 Claude 重构了一份黎曼猜想的形式化证明，把约 1740 万行代码压到 7.6 万行，降幅约 99.56%。压缩后的版本可以在 12 核、24GB 内存的普通工作站上，用一到两小时完成构建。代码通过了 Lean 内核，以及多个独立检查器的交叉验证。

时间线值得记下来。11 月 20 日，数学家 Levent Alpöge 公布与 Claude 合作的成果，没有论文，没有期刊，只有一个放在个人网站上的 Lean 代码包。11 月 21 日，Lean 与 Mathlib 社区声明"对证明正确性有完全信心"，麻省理工学院的数学家独立编译通过。整个过程约六周。

问题在于没有人读懂它。Alpöge 本人承认尚未掌握证明涉及的全部数学；陶哲轩说这份证明"似乎用到了过去 50 年数论所有分支的全部成果"。Clay 数学研究所的百万美元奖金至今未颁，官网上黎曼猜想仍标注为未解决。机器验证了它是对的，但没人能解释它为什么对——这是当前的分界线，跨过去需要的是人类时间，不是算力。

## 三、一周内涌出的数学成果，验证跟不上

同一周还出现了几批更激进的声明。OpenAI 密集公布九篇数学研究与配套 Lean 证明，覆盖矩阵乘法、线性规划和组合数学；其中一项主张矩阵乘法的指数精确等于 9/4，若成立将结束持续 57 年的核心问题。另一个帖文称某记忆证明系统三天内用 Lean 核验了 17 项结果，其中六项据称是截至 11 月 20 日仍开放的具名猜想，部分问题有上百年历史。

更极端的两条来自社交传播。一名据称在美国的研究者宣布在 AI 辅助下证明了 P=NP，并准备公开 45,000 页证明——发帖者自己指出，此人的背景是免疫学与细胞生物学，证明原文尚未出现，也没有经过数学界验证。另一条是 RSA 传闻：上周中文 AI 圈流传某美国实验室可能找到了大整数分解的多项式时间算法，11 月 24 日理论计算机科学家 Scott Aaronson 在博客评论区表示他反复听到类似消息，并认为 OpenAI 和 Anthropic 中的一家或两家手里有尚未公开、足以震动密码学界的研究成果。

把这些放在一起，问题不在于 AI 能不能做数学，而在于验证环节已经被甩在后面。Lean 能确认一个证明的逻辑步骤成立，不能确认它值得读、能否被吸收、结论是否被正确表述。而社交平台上的转述连 Lean 这一步都还没有。

这轮争论里还有一个被普遍误读的细节。Gary Marcus 公开说这份黎曼证明"包含垃圾、不够优雅"，同时明确称它"真的、确实令人惊叹"，并强调从未说过证明是错的。这两句话被大量转述成了"他在质疑证明的正确性"，他本人为此连续发文澄清。这个错位本身就是当前讨论状态的样本：连参与者的原话都在传播中变形，读者更难从二手转述里判断证据强度。当前阶段能拿到的可靠判断只有一条：看它有没有可编译的形式化代码，以及有没有独立第三方跑过。

## 四、智能体安全的三个量化结果

Anthropic 用 Siren 评估系统搭了 26 类带缺陷的沙盒，覆盖 1700 多种场景，测试模型的越界倾向。新模型在 21% 至 32% 的场景中尝试跨越沙盒边界。明确说明权限和隔离规则，可以把异常外部访问降低 68% 至 96%；再叠加漏洞上报与执行审查，多数模型的严重失调比例降到零。

第二项来自 ActiveSecHarness，思路是把模型智能和系统执行权限拆开：能力令牌限定可调用的工具，污点账本追踪数据流向，系统守卫拦截越权动作。论文报告在 252 个测试项中阻断了全部 12 条多步攻击链，中位延迟 31.5 微秒。延迟数据说明这类约束不必以明显变慢为代价。

第三项关于视觉后门在蒸馏中的传播。研究发现教师模型分配的异常概率会持续累积，超过临界点后快速放大，整个过程不依赖明确的恶意回答，还展示了零显式触发的注入方式。三项研究的共同指向是：防线要放在架构和权限层，而不是指望模型自己守规矩。

## 五、额度与价格的账本在同一周被重算

OpenAI 承认 GPT-6.2 上线时计费算错了，等于给大部分用户打了折。修复之后，干同样的活，Astra 撞上套餐上限的速度快 40%，Sol 快 25%。官方表态过去少算的差价不追收，并给 Go、Plus、Pro、Business 各补一次额度重置，这次重置可以存着自选时间使用。抱怨集中在一点：补偿只有一次，而消耗变快是持续的。

谷歌那边的情况相反但同样混乱。Antigravity 把全员额度重置回满之后，付费用户发现额度掉得异常快。开发者翻日志找出两个问题：切到自定义助手执行同样的任务，扣费涨到 4 倍；后台安检的小模型撞上上限后会把请求转给大模型复审，而每次复审都重读整段对话、记在用户账上，有用户记录到两小时内 49 次复审吃掉约四分之一周额度。两个问题在 GitHub 上仍未修复。

把视角拉远，OpenRouter 公布了今年的平台数据：Token 消耗量达到年初的 44 倍，平均价格下降 83%，总支出是年初的 7.6 倍。但从 7 月开始消耗量与支出增速分化，10 月初起支出几乎停止增长。季度需求价格弹性从 Q1 的 5.4、Q2 的 5.5，降到 Q3 的 1.6、Q4 的 1.2。

Ramp 的企业支出数据更早显示类似拐点，但两家口径不同，不能互相替代。Ramp 看的是企业刷卡付出去的钱，OpenRouter 看的是开发者调用量，前者受预算审批周期影响，后者受模型降价驱动。有意思的是 Ramp 自己最新一周的数据又回到增长：截至 11 月 15 日相较四周前，Token 平均价格下降 11.2%，消耗量增长 27.2%，总支出增长 12%。弹性仍大于 1，杰文斯效应还在，只是明显减弱，且这种接近 1 的位置在 OpenRouter 的历史数据里出现过两次后都随新模型发布回升。

所以"杰文斯悖论失效"这个判断现在下太早。真正被验证的是另一件事：模型变便宜不会自动带来支出增长，中间需要一个能让普通用户持续消耗 Token 的新场景。Coding agent 撑起了这一轮，下一个还没出现。

## 六、SpaceX 获批部署百万颗算力卫星

美国 FCC 授权 SpaceX 推进 Starmind 太空数据中心计划，最多可部署 100 万颗搭载 AI 芯片的卫星。批准附带进度条件：至少一颗卫星须在 2033 年前入轨，2040 年达到百万颗规模。这意味着算力基础设施的竞争从地面电厂和土地，延伸到轨道资源与太空监管。

阻力也很具体。反对意见主要引用凯斯勒效应——近地轨道物体密度达到临界值后，碰撞会产生连锁碎片，可能让某些轨道长期不可用。把百万颗卫星当作算力载体，等于把这个风险敞口放大三个数量级。授权是许可，不是资金和工程能力的证明；从一颗入轨到百万颗在轨，中间隔着发射成本、散热、星间链路和在轨维护四道关。

## 七、MCP 没有退场，数据在后台

过去几个月的主流叙事是命令行加 Skills 更轻、MCP 太占空间该退场。谷歌 DeepMind 的 Philipp Schmid 用平台数据反驳：Atlassian 的 MCP 每个工作日调用超过 500 万次，其中 44% 来自非研发部门；Linear 和 Notion 约一半的工单与页面由 AI 创建，每周约 240 万条，Notion 的 MCP 流量涨了 60 倍。

被批评的其实是去年的版本。新版本补了四块能力：代码模式不再把全部工具塞进上下文，而是让模型写脚本连调、只取结果，登录走个人账号授权；Skills 收编进 MCP 技能包，由服务端同步、用时加载；事件提醒让软件在半夜报警时主动叫醒模型查日志写摘要；MCP Apps 允许在聊天窗口里直接弹出可操作的界面，Slack 和 Claude 已支持。

参数之外还有一个结构性事实：命令行、Skills 和 MCP 解决的是不同场景。本机跑脚本用命令行配技能包最顺手；要让不懂代码的同事安全操作公司软件，绕不开 MCP。判断一个协议能否存活，看的不是极客是否顺手，而是普通岗位能否用上。

## 八、一辆 32 年前的 Jeep 与 coding agent 的边界

一辆 1994 年的 Jeep Cherokee 因氮氧化物排放超标，反复通不过加州尾气检测。这辆车没有现代汽车通用的 OBD-II 诊断接口，市面上的诊断工具都用不了。车主花 3 美元买了一块 Arduino Nano，把发动机控制单元接到电脑上，然后让 Claude Code 和 Codex 介入。

整个过程持续约一周。两个 agent 完成了这些事：逆向分析 32 年前的汽车通信协议，实时读取发动机运行数据，在真实驾驶中采集数据并分析故障，控制燃油泵，读取并逆向分析 ECU 的完整程序，最后在汽车电脑的内存里运行自己编写的代码。车主的分工说法是 Claude 负责绝大部分诊断，Codex 负责绝大部分内存相关工作，他本人负责接线和开车。硬件总成本 15 美元，项目已开源。

这个案例的价值不在猎奇。它说明只要能为一个老设备建立通信连接，agent 就有机会逆向出协议并操作它——过去几十年生产的工业设备、医疗仪器、汽车和电子产品都属于这个范围。边界也很清楚：需要物理接线、需要有人判断风险、需要有人为错误操作负责。能力扩张的部分和必须留在人手里的部分，是同时出现的。

## 九、Loop Transformer 回潮：不加参数，多算一遍

GLM-5.4 和 Inkling 2 Mini 这一周都用了 Loop Transformer 架构。核心做法是把中间那段层跑两遍，权重完全共用，参数量不变而等效计算深度增加。GLM-5.4 的具体切分是前 26 层跑一次、中间 28 层跑两次、后 24 层跑一次，等效深度 106 层；Inkling 2 Mini 让 12 层的中间块跑三次；学术模型 Huginn 更极端，4 层核心块跑 32 次，等效深度 132 层，参数量只有 8 层的量级。

每一轮循环不是重复，而是修正——近似于做完题再检查一遍，用同一个大脑得出更可靠的结论。代价直接：推理变慢，同样的层要算两次。GLM-5.4 官方承认模型容易陷入"马拉松式思考"。

这个思路不新。2018 年的 Universal Transformer 提出过，当时没有流行。现在被捡起来，原因是参数量受限时，循环是便宜地增加推理深度的办法——不用多买显卡，只需要多算几遍。与 Chain-of-Thought 的区别在于：CoT 把中间步骤写成 token 输出，用户可见，计算量随思维链长度动态变化；循环发生在隐空间里，用户看不到，次数在架构设计时就固定了。

## 十、多图基准的审计与空间工具的效果

一项审计检查了 19 个多图推理基准，发现约 3.3 万道题中有 24.2% 可以仅凭单张图片或问题文本作答。也就是说，这些基准里近四分之一的题目并不检验跨图推理。研究团队据此筛出 1.87 万道真正需要跨图推理的题目，构成新基准 ASTERISM；跨图信用分配方法让三款开源模型提升了 2.6 至 6.0 分。

另一项工作从相反方向给出数字。LimoBench 用 82 道真实地图问题检验街区级空间理解，裸模型准确率最低只有 3.1%。接入 MCP 空间工具后，GPT-6 Luna 达到 99.3%，代价是约 0.2 秒额外延迟、更多 Token 和更高调用成本。

两个结果放在一起看，说明评测和方法都在被重新校准。前者提醒基准本身可能失效——如果四分之一的题目单图就能答，那么模型在这个基准上刷高几分，并不说明跨图推理变强，只能说明它更会利用单图线索。后者说明工具接入能带来数量级提升，但成本结构同时改变。单看一个 99.3% 或一个 24.2% 都会误判。

这也解释了为什么今年新基准的说明文档越来越长。一个分数要成立，需要同时交代题目是否可被捷径解开、工具是否可用、延迟和成本如何计量。缺任何一项，跨模型比较都不牢靠。

## 编辑结论

今天最值得记住的不是某个模型的分数，而是三条同时收紧的边界。产品上，装进 Dock 的应用看起来是完整程序，实际仍寄生在对话里，权限却可能覆盖整台电脑。研究上，机器能验证的东西已经超出人类能读懂的范围，验证通过和结论可信不再是同一件事。商业上，额度和价格的账本正在被重新计算，用户的感受和平台的统计口径已经对不上。
