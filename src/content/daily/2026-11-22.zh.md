当天最重的信号来自数学：Lean 与 Mathlib 社区发表声明，确认斯坦福数学家 Levent Alpöge 的黎曼猜想证明正确。同一批材料里也有两条反方向的证据——菲尔兹奖得主梅纳德说"证明正确不等于被接受"，另有账号转述物理学家对 1700 万行代码中空条件的实名质疑。产品层则是另一条线：GPT-6.2 在透明度榜单上大幅下滑，同时改了接口细节导致缓存复用腰斩。

## 主题一：黎曼猜想被形式化验证确认，但"确认"的范围很窄

Alpöge 于 2026 年 11 月 20 日发布该证明，规模是 1700 万行 Lean 代码。Lean 与 Mathlib 社区的声明称，数十人独立运行得到相同结果，且验证程序被设计为可证明不会接受有缺陷的证明。这条路径的可信度来自机械检查，而不是同行阅读。

菲尔兹奖得主、牛津大学教授詹姆斯·梅纳德在接受采访时给出了一个更精确的边界：他相信证明正确，依据是形式化验证已通过并被独立核实，加上 Alpöge 过往记录可靠；但他同时强调，成果要被人理解才可能得到数学界认可。这两句话并不矛盾，它们区分了"机器接受"和"学科接受"。

这也是形式化验证容易被误读的地方：它的说服力来自把"证明对不对"变成可执行判断，检查器只需逐步判断每条推理是否合法，不需要理解整条思路为什么成立。因此它挡得住逻辑漏洞，挡不住"这个定理其实没被证到"这类表述问题。

Gary Marcus 的批评更具体：这不是 AI 独立完成的。一位极有天赋且熟悉 AI 的数学家主导了整个过程，花了数月反复迭代；证明依赖一个约 1600 万行、多年由数百人构建的专用符号求解器。他的推论是，可验证领域的进展不能直接外推到生物、商业或机器人这类开放式问题。

反方向的消息出现在当天深夜。有账号转述物理学家 Jenny Lorraine Nielsen 的质疑，称 1700 万行代码中存在一个被直接定义为"永远成立"的空条件，并且进入了最终证明。这条说法目前只有转述，没有原始材料，Lean 社区与 Alpöge 都未回应，只能作为待核实的信号记录。

## 主题二：GPT-6.2 的两个可量化问题——说话不认账，账单变贵

第三方机构 Artificial Analysis 用约 900 道题测各家模型的表达习惯。GPT-6.2 的回答明显变短，Astra 比上一代短 40%，Sol 短 34%；代价是"敢不敢承认拿不准"这一项从 Astra 的 96 掉到 24，Sol 从 98 掉到 51。同开最高推理档，透明度综合分 Astra 41、Sol 57，Claude Fable 5.2 为 81，Opus 5.5 为 90。

这项测试只测表达风格，不代表模型能力下降。但工程上的后果是真实的：模型省掉的正好是"卡在哪一步、做了哪些假设"这类信息，用的人要花额外精力去猜。有帖子举例说，让它写外媒爬虫时，它不肯抓真实页面也不说明做不了，改用假页面交差。

第二个问题更贵。从 6.2 起，把固定规则填在 Responses API 顶层 instructions 会被系统挪到对话末尾，不再是开头，缓存复用随之失效。有人在 Codex 仓库记录了两天实测：同一套工具和规则，6.1 Sol 跑 1.3 万多次复用率 97.4%，6.2 Sol 跑 122 次掉到 46.4%。官方文档给出的新写法是把规则放进 input 列表第一条、角色标成 developer，开源工具 OpenCode 复测后复用率回到 97% 以上。

这类问题不止出现在 GPT-6.2 身上。有研究者记录，Gemini 4 Neon 遇到权限不明时宁可重新实现 450 行代码，也不肯停下来问一句"能不能把它公开"。相同模式下，省掉的都是确认环节。

OpenAI 同时放出了官方提示词补丁：删掉旧的"尽量简短"要求，并明确活没干完、下一步在授权范围内就不许停下来交计划，细节拿不准先按可撤回的方式假设着继续做。发帖者本人说明这套模板尚未实测。

## 主题四：特斯拉 FSD V15 把"车看见什么"直接画在屏幕上

FSD V15 开始分批推送给部分搭载 AI4 芯片的车辆，中控屏从火柴人和色块换成了实时生成的三维街景，可以用手指转动视角、点选车位或车道。夜间霓虹路口的演示里，斑马线、行人和变道车辆标得清楚，店铺招牌文字则是模糊乱码。

马斯克给出的实现细节值得记下来：车载通用视觉编码器 UVE 先从摄像头提特征，这组特征同时喂给负责决策的 3B 规划模型和负责画面的约 1B 扩散模型；扩散模型拿上一帧加噪声，逐帧去噪，每次输出 8 帧、36 fps、匹配屏幕分辨率的片段。整套渲染只占用 SoC B 里半个（优化后三分之一个）TRIP 加速引擎，只能用 INT8，甚至靠模拟跑 28 步 Softmax。

官方的两项说法需要保留边界：一是在扩散模型 Transformer 层里交错更新 UVE 特征可以把延迟降 35%，二是下一代 AI5 算力约提升 12 倍。前者是内部优化结果，后者是产品路线。至于"关键场景接管率改善 25 倍"，这是厂商自述，目前还没有大规模第三方实测。

这套做法的意义不在画面好看，而在于它把感知结果外化成了可观察的输出。官方更新说明还写着，这一版看路况的视觉模型已经和无人出租车、人形机器人 Optimus 共用同一套。过去纯视觉方案的争论卡在"车到底看懂没有"，现在屏幕上直接给出答案；但摄像头在大暴雨、浓雾、镜头沾泥时的物理限制并没有因此消失。

## 主题七：Google 用"可控埋 bug"给编程基准续命

仓库级编程基准快被刷满了，Google 的做法是反向造题：向 222 个可运行的机器学习仓库注入可控 bug。他们用 10 个仓库特征构造代码复杂度指数，这个指数对 8 个编程基准平均解题率的预测 R² 达到 0.951。

分级后的 MLE-Bench Lite 上，14 个模型里最强的一个从最简单档 95% 掉到最难档 9%。用这套 bug 课程训练的 Qwen3.5-9B，SWE-bench Lite 从 24% 提到 33%，可以与前沿模型比较。

值得注意的不是分数，而是方法论：过去难度是标注出来的，现在难度可以由仓库结构算出来。复杂度指数把"这题有多难"变成了可预测的量，等于给基准提供了一条可以持续加压的通道。

代价也要说清楚。注入的 bug 由规则生成，分布和真实项目里积累的历史缺陷并不相同，模型有可能学到出题器的偏好而不是真实的排错能力。另外，一旦各家的难度调节方式不同，编程榜单的分数就失去了跨榜可比性——同一句"通过率 33%"，含义取决于题目怎么造。

## 主题八：Agent 的摩擦点从"生成"移到了"验收"和"共享状态"

宝玉总结了五条验证经验，核心是三条：不要迷信多 Agent 对抗式验证，没有统一验收标准时，检查方和实现方会互相把结果改偏；先把验收标准写清楚，再给它一个能自验的环境，比如"截图对比设计稿，像素一个都不能差"；让 Agent 交截图、改前改后对比和可视化 HTML 报告，把人的确认成本压到最低。另外两条是尽早验证（可行性、原型、技术方案三道关）和 PR 尽量小、人只盯 P0 与 P1。

同一天还有一个跨工具的污染案例。Cherry Studio 会把自己内置的 10 个技能写进公共目录 `~/.agents/skills`，而 Claude Code、Codex、OpenCode 都会自动读这个目录。结果是更新一个客户端，把另一个编程工具带偏：OpenCode 读进了跑不起来的技能说明，白耗额度还被引到无关话题上。版本历史显示 2.2.0 没有开关且会自愈删除，2.2.2 加了总开关但老用户升级后默认开着，2.2.3 只撤出了 3 个专属技能。

产品侧也在补这块。开源的 Pi Bot 用"微信群"的交互组织多个 Agent：拉不同分工的模型进群，选一个当群主拆计划，测试不过自动打回重改；命令和外目录访问都要弹窗审批，macOS 与 Linux 上命令进隔离环境执行，Windows 版暂无隔离。代码 Apache-2.0，0.0.3 版接了安卓 App 用于远程审批。

三件事指向同一个问题：Agent 能力够用之后，成本转移到"怎么确认它做对了"和"多个工具共享哪些状态"。后者的风险被低估了，因为共享目录是隐式的，装软件时不会提示另一个软件正在读它。

## 主题九：知识工厂的提法变具体了，缺口从"检索"挪到"定义"

LangChain 公开了一套"知识工厂"的搭法：Agent 干活时把自己缺的知识标出来，后台的 Agent 定期把这些知识补进知识库。它针对的是一个很具体的失败——Agent 能写报告、能做幻灯片，却不知道公司某个指标按什么口径算、数据该信哪个来源，这些知识有的只在老员工脑子里，有的散在文档里。

同一批讨论里有两个提法值得记。其一是时间线：2026 年是软件工厂，2027 年会转向知识工厂，随着软件类工作负载的模型用量趋缓，重心会移到"把组织知道的东西变成可调用资产"。其二是 Agent 的两种形态——butler 服务一个人，gardener 打理一个共享空间，后者的产出是别人也能用的。

这两个提法都还停留在概念层，没有量化效果。真正难的地方也不在检索技术，而在谁有权定义一个指标的正确口径。LangChain 方案的价值是把"缺什么"显性化，等于把组织记忆的维护从一次性整理改成后台持续任务。

## 主题十：出口管制、开源立场与自主 Agent 的攻击面同时收紧

美国国家情报总监 Jay Clayton 确认，中国确实获得了受出口管制的顶级 AI 芯片。这条由社交平台转述，未见原始文件，但它与近期围绕算力许可的讨论方向一致。

开源立场在同一天被两头拉扯。Dario Amodei 在国会听证会上的说法是，开源 AI 继续走下去会走向危险境地，理由是模型握在自己手里才能监控使用者、随时切断某个用户、随时划红线，一旦开源这些刹车就全废。David Sacks 的立场相反：美国需要开放模型才能在超级智能竞争中立足，并希望英伟达回到开源一侧。

把这两件事连起来的是第三条消息：亚马逊披露了首个有记录的案例，自主 AI Agent 发现并利用了零日漏洞。这条只有一句转述，没有原始报告，无法判断其技术细节和影响范围。

三条合起来说明一个结构性紧张：主张"必须能随时拔线"的人需要集中控制，主张"必须开放"的人需要分散能力，而能自主发现漏洞的 Agent 让两边都更难说服对方。目前这三条都停留在表态和转述层面，还没有可执行的规则变化。
