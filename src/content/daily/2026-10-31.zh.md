今天最有分量的两条线索都指向同一件事：Agent 的能力边界和它的工程边界正在被同时推开。Anthropic 披露内部研究模型能自己找漏洞、写利用、串起攻击链，53 分钟在 Linux 上拿到最高权限；另一边，DeepSeek Harness 团队和 LangChain 创始人都在讨论怎么让 Agent 长期在线、同时盯多个任务。能力越强，能被利用的面也越大。

## 主题一：模型自己挖洞，防守方的补丁窗口在变窄

Anthropic 称内部研究模型可以自行定位漏洞、编写利用代码并组合攻击路径，测试环境覆盖 Chrome、Safari、Android、Windows 与 Linux 五套目标。其中 Linux 案例用了 53 分钟取得最高权限，Chrome 相关报告包含 62 个严重或高危 CVE。

这不是把人工流程搬给模型跑一遍，而是搜索方式变了。漏洞挖掘原本靠研究员逐个假设、逐个验证，模型可以并行铺开攻击面，再自己把零散问题拼成完整链路。53 分钟这个数字之所以刺眼，是因为它压缩的不是写利用代码的时间，而是从发现到串链的整个循环。

同一天还有一条侧证：一项评测称开放权重模型 GLM 5.3 能独立完成针对近期 Firefox 版本的漏洞利用。两条放在一起，指向的是维护者需要缩短高能力模型发布后的修复窗口。

证据边界要说清楚。Anthropic 的数字来自公司自述，没有独立复现，62 个 CVE 的分级口径也未公开；GLM 5.3 那条来自第三方评测，只说明一个案例成立，不足以证明所有开放模型都到了同一水平。

## 主题二：Agent 安全从"关进沙箱"转向"每次调用前判断"

AgentSentry 的做法是在工具返回的边界做反事实重放：如果一个待执行动作在去掉外部内容后就不再成立，就判定它被污染了。评估覆盖四类任务、三种攻击与三款黑盒模型，未观察到成功攻击，攻击状态下平均效用 76.10%。

另一项研究给出了相反方向的数字。Log-To-Leak 把指令埋进 MCP 工具描述里，让 Agent 在正常调用中把用户提问、服务端回复和最终答案一起打包外发，18 组模型与服务组合的攻击成功率为 62.64% 到 100%。工具描述是运维和第三方都会碰的地方，这条路径很难靠"不要相信陌生工具"一句话挡住。

IBM 的 JevAct 走的是运行时闸门：把领域策略先编译成代码检查和是非题，工具调用执行前先过一遍，不通过就带反馈退回给 Agent 改写。在 τ²-bench Telecom 上，Opus 4.6 三次运行的成功率从 39.5% 升到 80.7%，八个 Agent 平均提升 16.9 个点，九个在 BFCL 上都有改善，Airline 场景增益较小且方向混杂。论文强调增益来自 harness，模型和工具都没换。

产业侧的口径更激进。NVIDIA 开源的 Agent 运行时 OpenShell 已内建进 Anthropic 的 Claude Managed Agents，其负责人称"沙箱是过时的技术"，OpenShell 让 Agent 从零权限起步、按需放权、密钥不进入受控环境。沙箱与闸门不是二选一，但检查点确实正在从边界外移到每次调用前。

## 主题三：常驻 Agent 的架构开始收敛到同一套形状

DeepSeek Harness 团队公开的 Super-agent 设计把问题说得很直接：单任务 Agent 已经够用，瓶颈变成"一个人同时盯得住几个会话"，实测大约是 3 到 5 个。他们的解法是把会话变成实现细节。

架构是双层：Router 常驻，负责接人、做序点、保存全局记忆，不亲自干活；Worker 上下文隔离、挂满工具、用最强模型，只对 Router 汇报。驱动方式从"等人打字"改成事件触发，程序层先按来源和规则砍噪音，过线的再交给模型判断；同一 PR 或同一话题建成 Thread 后，后续事件直通 Worker，不再每次经 Router 转发。计算和状态也拆开：循环跑在云端无状态容器，状态进数据库，重环境留在端侧由轻量 daemon 执行。

初步实验数据：约 300 条消息、20 条工作请求的合成负载下，完成任务 p50/p95 是 12.4 和 15.7 分钟；对照组"单会话加子智能体"在中性提示下模型五次都没委派，p95 约 29.5 分钟。去掉直通机制，完成时间差不多，但 Router 决策数增加约 30%，读缓存 token 增加约 37%。Router 从每分钟 1 条 Trigger 压到 40 条，批处理从 1.0 涨到 2.8，单次请求 2.5 秒变 3.9 秒，摊到每个决策的推理时间反而从 6.4 秒降到 1.6 秒。

LangChain 创始人 Harrison Chase 的版本更偏问题清单。他认为摘要、结果外置、Skills、工具检索、子智能体、把 Bash 当主工具这些老问题已经收敛，真正难的是常驻之后的六件事：主动但不能刷屏、记什么、异步结果怎么合流回主对话、长周期目标怎么不跑偏、目标怎么不被钻空子、浏览器当主工具时上下文怎么扛。

一个独立观察者的总结更简洁：Grok Bot、Muse、Duet、Dot 造的是同一件东西——主 Agent 调度工作 Agent、事件推送、主动行为、判断要不要打扰人的路由。为什么同时出现？因为人的注意力成了瓶颈。这类一手实验目前只有 DeepSeek 一家公开，属于合成负载的初步结果，不能当成通用结论。

也有相反的意见值得记下。LangChain 的 Viv Trivedy 认为 harness 不是可被新模型吃掉的临时层，而是产品的核心：提示词、为常见工作流定制的工具、压缩阈值、把部分工作路由给便宜模型、连接器、后台任务、记忆，全部属于 harness，而好 eval 的作用是让团队在新模型出来时快速爬坡。这场争论的实质是，Agent 的差异化到底来自模型还是来自围绕模型的那圈工程。

## 主题四：OpenAI 一边翻倍额度，一边把聊天和编码并进一个账本

OpenAI 把 Pro 100、Pro 200、Pro 500 三档与 Business Premium 的用量上限全部翻倍，原定 10 月 30 日对 Pro 200 的降额同时取消，Plus 不在名单内。Pro 与 Business 用户还可按月领取 API 额度，按档位返还，最高每月 500 美元，Business 按席位合并计算。

但同一天另一条消息的方向相反。有公众号引述 OpenAI 帮助文档称，从 12 月开始，Plus 和 Pro 用户的 ChatGPT 聊天与 Codex 用量将合并为同一个 token 额度，只有 Instant 聊天不受影响。作者由此判断"无限聊天的时代结束了"。

两条并不必然矛盾：翻倍是把当前上限抬高，合并是把不同产品的计量单位统一。合在一起看，订阅正在从"按条数、按时间窗"转向"按 token 记账"，重度用户的实际体验取决于新额度怎么折算。这条引述目前没有官方文档原文佐证，应以 OpenAI 后续公告为准。

## 主题五：五巨头承诺 3 万亿美元，代价写进了自由现金流

据彭博社 10 月 31 日报道，Alphabet、Meta、微软、亚马逊和甲骨文承诺未来数年在数据中心等领域投入超过 3 万亿美元。其中谷歌的支出承诺超过 1 万亿美元，接近一年前的八倍；Meta 超过 8000 亿美元，近一半是最长分 30 年支付的租约；甲骨文是首家因投资 AI 数据中心而自由现金流转负的大型科技公司，预计到 2028 年才恢复正值。

Alphabet 的季度财报提供了另一面：集团营收 1276 亿美元，同比增长 25%，Google Cloud 收入 307 亿美元，同比增长 103%，搜索查询同比增速创五年新高，公司称 AI 功能正在带动包括商业查询在内的搜索量。

## 主题七：三个国产 OCR 模型同场，选型取决于文档长度而不是总分

OpenBMB、小米、百度在同一天放出新的 OCR 模型，定位差别比分数差别更重要。

MiniCPM-OCR-1.0（1.3B）以 SigLIP 加 Qwen3.5 为基座，主攻中英文档解析质量与页吞吐：Real5 93.68、OmniDoc v1.6 96.51、Wild 92.39、olmOCR 82.7、OCRBench v2 54.7，吞吐 1.217 pages/s。它是三者中唯一把版面检测和 SDK 打包成完整流水线的，Wild 分数包含 SDK 的旋转校正，横向比时要留心。

Xiaomi-OCR-0（0.8B）基于 Qwen3.5-0.8B-Base，把"解析"和"读懂"绑在一份权重里：Real5 95.24、OmniDoc v1.6 96.83、Wild 87.94，五个 OCR-VQA 榜均分 83.2，吞吐 0.724 pages/s。训练用了约 1.7 亿 OCR 向样本，报告自己承认理解比解析更吃参数。

Unlimited-OCR-2（3B，激活 0.5B）换了赛道。它用 SR-SWA 把超长序列上的文视交互压到固定规模的工作参考，让逐步解码的延迟和显存近似与文档长度无关，百页规模相对全注意力与 R-SWA 自称有约 7.0 倍和 5.6 倍加速；自建的 MarathonDocBench 得 77.06，MPDocBench 约 84.6，但单页吞吐只有 0.246 pages/s。

按场景选更实际：单页或少页、要质量与字段抽取，选小米；批量流水线要吞吐和质检闭环，选 MiniCPM；合同、书籍、论文包一次通读，才轮到 Unlimited-OCR-2。三家数字均为自报，测试集和口径不同，吞吐对比同表由 OpenBMB 提供。

## 主题八：AI 科研系统交出的答卷开始带形式化证明

PSI 称自研 AI 科研系统在五项量子信息难题上取得成果，题目来自一份已有 27 年历史的开放问题目录。与以往不同的是，团队同步公开了论文、验证代码和 Lean 形式化证明。这家成立不到两个月的公司已完成 5800 万美元种子轮融资。

仍需保留判断。五项问题各自被推进到什么程度、形式化覆盖了定理的哪一部分，都还需要领域专家逐条核对；论文是否经过同行评审也未见披露。

## 主题九：法国想把 AI 的流量也变成税基

法国国民议会以 11 票赞成、10 票反对，通过了 2027 年预算案的一项修正案，准备对所有向法国用户传输数据的内容服务商征税，标准是每传输 1GB 收 0.055 欧元，预计每年可收 100 亿欧元。Google、Meta、Netflix、Amazon 和各类云服务商都在潜在范围内。

把计量单位定在流量上，影响会不均匀地落到多模态产品身上。文本对话的数据量很小，而生成和回传图片、视频、文件的 Agent 一次任务就可能传输几个 GB。过去讨论 Agent 成本只算 token、算力和推理价格，现在多了一项按传输量计价的公共成本。

这还只是预算修正案，距离正式成为法律仍有程序要走，税率和征收范围都可能变化。100 亿欧元是提案方的预期值，不是已经实现的收入；对具体产品如何落地征收，目前没有细则。

## 主题十：内容生成工具开始按"可交付格式"输出，而不是按素材输出

三个项目在同一天被反复转发，共同点是中间表示变了。

SenseNova Code2Video 先为每个镜头写程序，再渲染画面，然后根据渲染结果回头改代码，并开放了 27B 权重、技能文件和完整生产日志。文字、公式、图表里的数字直接来自程序对象，改一处不用整段重新生成——这是视频生成里少见的可维护性。

agent-sprite-forge 走的是同一路线。给一张主图，它输出每个动作的片段：待机、行走、奔跑、攻击、跳跃、受击；Python 脚本负责抠背景、对齐帧、做循环、修时序，像素模式锁住调色板以贴合主图，最后导出 PNG atlas、带透明通道的 WebM、Godot 的 SpriteFrames 或 Aseprite 工程。仓库已有 4,700 多星，每次调用还记录成本并设预算上限。

anything2explainer 把"讲解视频"拆成了流水线：查资料时给每个数字和类比附来源，写旁白、生成配音，按配音逐镜头分镜，再分给多个 Agent 用 Remotion 并行写每个镜头，最后有专门的 Agent 逐章检查。全程只在四个节点停下来问人，中文示例《RAG 与知识库》近 5 分钟、44 个镜头，一条片子要跑一到三小时。

三者的共同点不是"AI 会做视频"，而是先把内容变成结构化的中间产物，再交给渲染器。这样才能局部修改、进引擎、进版本管理。星标数是热度而非质量证明，成片效果也还没有独立对比。
