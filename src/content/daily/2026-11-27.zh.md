今天最集中的变化不在模型能力，而在 Agent 的权限与验收方式。Anthropic 把代码审查、自动修复和规则审批拆成三个互不重叠的组件，Google 与吴恩达分别用四层框架和评测纪律描述同一件事：能力靠循环，可靠靠门禁。同一批抓取里，MCP 的支持者拿出真实用量数据反驳“命令行取代 MCP”的判断，而 AI 参与数学证明的消息旁边，紧接着就是同行对夸大叙事的反驳。

## 主题一：代码审查被拆成三个角色，自审自批被切断

Anthropic 推出代码协作套件 Claude Ship，把只读审查、自动修复和规则审批交给三个独立组件。设计目标是让同一个代理不能既写代码又给自己放行。审批策略只从默认分支读取，提交者无法借待审代码顺带降低门槛。

Anthropic 给出的内部数据是：PR 合并量在三个月内翻倍，回滚比例下降超过 40%。合并量与回滚率同时改善，说明提速并非只靠放宽标准，但这两个数字来自厂商自述，没有独立复核。

同一天另一组研究解释了为什么“必要性”必须单独检查。研究者回放 7660 条轨迹，逐块撤销智能体补丁并重跑测试，在 SWE-bench Verified 上发现约 11% 的代码单元并非任务必需，其中 89% 仍会改变程序行为。多余改动不等于无害改动。研究建议基准同时报告任务解决率与代码必要性。

把两件事放在一起看：当生成量足够大，瓶颈从“能不能写”转移到“谁有权批准”和“如何证明这行代码该存在”。前者是权限结构问题，后者需要可复现的判定方法，两者都难以靠一句“小心一点”解决。

证据边界：Claude Ship 的内部指标未经第三方验证；补丁必要性研究建立在单一基准的回放实验上，比例外推到其他仓库需要谨慎。

## 主题二：MCP 的支持者用用量数据回应“被命令行取代”

Google DeepMind 负责 Agents 与 Gemini API 的 Philipp Schmid 写了《Why I'm Bullish on MCP for 2027》，回顾 MCP 被热捧、又因上下文膨胀遭到反弹、随后 Skills 与命令行兴起的 18 个月。他的判断是风向正在回来，并给出了一组具体用量。

Linear 与 Notion 里，Agent 已创建约一半的 issue 和页面，issue 约每周 240 万条，Notion 称 MCP 流量增长 60 倍；Atlassian 每个工作日有超过 500 万次 MCP 工具调用，其中 44% 的使用者不在软件团队，“命令行本来就不是选项”；Neon 上经 MCP 的智能体用量每周增长 14%；苹果已为 Pages、Numbers 和 Keynote 提供本地 MCP 服务器。

技术上的关键补丁是 Code Mode。服务器同时给出 inputSchema 和 outputSchema，客户端先生成带类型的接口，模型在沙箱里写一段脚本连续调用、在内存里过滤拼接，只把摘要送回上下文，中间结果不再反复堆进模型窗口。鉴权也移出沙箱，按用户的 OAuth 2.1 与权限范围由客户端处理，不必把宽权限密钥写进磁盘。Schmid 称这已在 OpenCode 2.0、Claude Code、OpenAI Codex、Pi 和 Factory Droid 里逐渐成为默认。

另外两项扩展补上了过去的短板。Skills over MCP 给每个 Skill 一个 skill:// 地址、解析过的 YAML 头和带 SHA-256 摘要的文件清单，厂商更新后摘要变化，客户端可自动拉取，Anthropic 已在 Claude 与 Claude Code 中以公开测试形式提供，Shopify、HubSpot、Atlassian 可按账号或组织下发说明。Events 扩展提供 webhook、推送与轮询三种送达方式，让外部系统能把智能体叫醒，而不是只能等它来拉。

他也列出缺口：服务器常常只看见工具调用，看不见用户在谈什么；发现机制要向多家注册中心重复提交；不受信任的 webhook、Code Mode 沙箱和嵌入式页面都会扩大提示注入面。这些用量数字多数来自厂商公开表述，方向可信，量级未经审计。

## 主题三：Google 与吴恩达把 Agent 可靠性拆成同一套纪律

Google Cloud Tech 的一期节目里，五位 Google 工程师把生产环境的 Agent 拆成学习、守卫、评审、打分四层。学习层管动手前的上下文：一份简短的仓库地图、写在磁盘上的计划和任务清单、按需加载的 Skills。给几十页规则塞进系统提示，上下文会被撑爆，写代码反而更差。

守卫层强调模型不能讨价还价的底线。编译器、类型检查、固定输入的测试、lint、密钥扫描、依赖成分分析和按规则做的安全测试，每次结果都一样，比让模型再表态更便宜也更快。新写的测试如果一写出来就通过，说明没测到新行为，应直接退回；改了已有测试、测试数量或覆盖率下降，就在 git hook 里卡住。门失败时把原始日志和行号送回，重试次数设上限，例如三次，再不行交给人。门本身不许 Agent 修改。

评审层的原则是生成与批评分开：写代码的 Agent 不给自己打分，Harness 另起独立评审，在全新上下文里对照工程标准看 diff。面对动辄很大的 AI 生成 PR，工程师 YK 主张能拆小就拆小，拆不动就换几种切法，例如先让模型给每个文件写一句摘要，或把 diff 做成可交互的可视化页面从架构角度看。

打分层评的是整套系统而非单句回复。模型可以说“已退款”，但它不会真的去操作。要评工具选择、参数、顺序是否正确，要容忍同样的测试得到两种回复，要测多轮里订单号被改过后是否还退对，还要测多 Agent 交接有没有交给对的专长角色。

吴恩达在斯坦福 CS329Z 的对谈里给出同一结论的行为版本。他说做得好的团队和做不好的团队，最大差别是能不能回到有纪律的错误分析，并用评测驱动开发。多数团队能靠快速试错从零做到约 80% 准确率，之后就在提升和回退之间打转；要往 90% 以上走，需要黄金测试集和回归测试。

评测本身也暴露出能力缺口。EgoUseBench 用动态第一视角评测集，从 74 小时真实记录中构建 693 项任务：执行期间用户要求、第一视角观察和网页状态会持续变化。在线场景的平均成功率比普通计算机操作低 26.3%，说明持续校准环境与用户意图仍是主要短板。静态任务上的分数好看，不等于在会变的场景里还能用。

他还区分了可验证任务与判断题：写代码、证定理有客观对错，可以搭强化学习环境自动打分；而选架构、排功能优先级、定营销口号、要不要现在招销售副总裁，都没有唯一答案，却有好坏之差，让模型变好需要大量专家标注，过程更慢也更痛。评测天然偏向可验证任务，社会又容易把个别突破外推。

对“把思考外包”，他的态度明确：聊天机器人被设计来把事情做完，本来就不是为学习准备的，他引用宾夕法尼亚大学一项研究，用聊天机器人的学生闭卷成绩低了 17%。他自己几乎不再逐行审代码，改用严格测试、护栏和沙箱建立信任，并提到智能体曾删过生产数据、留下过测试用后门；Diyi Yang 则表示短期内不同意完全跳过审查。

证据边界：Google 的四层来自自家生产经验，非对照实验；17% 是对单一研究的转述。

## 主题四：AI 参与数学证明，同行当场划出夸大的边界

Gemini 4 Carbon 提出了三维哈德维格猜想的证明骨架，两名研究者据此完成关键引导与严谨论证。最终数学证明只有六页，配套的 Lean 验证工程达到 13725 行。这件事的价值在于链条完整：模型提思路，人补论证，形式化工具逐条核验，整条链路可以被第三方重跑。

六页证明对应一万三千多行验证代码，这个比例本身就是信息。把自然语言的推理变成机器可检查的对象，成本主要落在形式化这一侧，而这一侧目前仍由人设计规格、判断该证什么。

同一天的公开讨论给出了必要的反向参照。François Chollet 批评“2026 年数学进展超过过去 140 年”的说法是纯粹博取互动：1880 到 2025 年之间建立了公理集合论、范畴论、代数拓扑、博弈论、信息论、混沌理论和现代统计学，而 2026 年对数学的理解与 2025 年相比几乎没变。他的追问很具体：那些“数学未解问题”是从哪来的。

证据边界：该猜想的证明是否通过同行评审未见公开说明；Chollet 的反驳是公开批评，不是论文。两件事都成立，也不互相取消：模型确实参与了原创构思并被形式化核验，但由此推导整个学科进度是另一回事。

## 主题五：世界模型进生产线，具身智能先解决“记得住路”

小米发布汽车世界模型 2.0，把多视角视频生成、三维重建、物理交互与动作建模接进统一架构。模型用 1260 万段视频训练，支持 1 至 7 路摄像头，已用于合成数据生产和闭环仿真；项目累计生成超过 20 万段合成数据，并投入感知训练。

蚂蚁灵波的动作更偏端侧。它发布机器人空间记忆模型，让设备在移动建图时持续纠偏，并在新任务中复用历史观察；LingBot-Map 2.0 纠偏后的轨迹误差降到 4.72 米，LingBot-Navi 可依据已有记忆规划路线。两款模型支持端侧运行，代码、权重和数据集均已开放。

两个方向回答同一个瓶颈的不同半段。世界模型解决“真实数据不够”，用可控的仿真补齐长尾场景；空间记忆解决“误差会累积”，让设备不必每次从零建图。前者是数据生产管线，后者是运行时能力，都属于把模型接进真实业务时必须先修的地基。

训练数据这一侧还有一个更便宜的路线。DemoFoundry 让编码智能体与生成式渲染协作，自动编写交互程序、执行物理仿真并生成写实机器人视频，同时保留状态和动作标签。由合成示范训练出的策略优于原始仿真训练，并接近使用同等数量真实示范的效果。

证据边界：小米未公布这些合成数据对下游指标的贡献，20 万段是产量而非效果；4.72 米是特定场景下的轨迹误差，不能外推到其他机器人或场地。

## 主题六：开源权重往两端走，224B 进主机、30B 只激活 3B

腾讯混元开放了 Hy4 flash 的量化权重和配套推理代码，224B 模型已在 64GB Mac mini 上跑通。最小 IQ2-AH 版本为 125.73 GiB，相比原始约 410.27 GiB 缩减约 69%；Q3_K 在四项评测中与原模型的分差均未超过 0.4 分。

英伟达公开 Nemotron-Labs-Image-30B-A3B，采用 300 亿参数 MoE 架构，运行时只激活 30 亿参数。模型可生成网页、图表、文档和科学插图等可编辑内容，LongTextBench 得分 97.98、GenEval 得分 92.86，但在 GenEval2 和 Qwen-Image-Bench 上仍落后于 GPT Image2。

两条路线指向同一种经济性变化。量化把“能不能跑”推进到“差 0.4 分以内能不能接受”，端侧部署的门槛从显存转向可容忍的精度损失；MoE 让 30B 的知识容量配 3B 的推理成本，生图模型也开始按这个结构设计。

证据边界：0.4 分只覆盖四个评测，换任务后是否同样稳定未知；图像模型的自评基准与主观可用性之间有距离，落后项恰好出现在更难的组合基准上。

## 主题七：被“遗忘”的知识，可能只是被压住了

Anthropic 的一项研究发现，模型的遗忘机制有时只是压低答案的输出，并未真正清除内部知识。在受测的 23 个模型里，有 14 个仍会把原来的正确答案排在概率首位。部分模型只需回调几十个神经元，相关能力便会重新出现。

这个结果直接影响能力删除的评估方法。如果只看输出是否还提到某项知识，会把“被压制”误判为“已删除”；更稳的做法是同时检查概率分布和内部机制，确认答案是不是仍然排在最前。

它对部署场景的意义具体而现实：靠微调或系统提示隐藏某项能力，不构成安全边界。模型仍然具备该能力，只是当前不表达。任何把“已移除”当作结论的合规声明，都需要说明检测的是输出层还是内部表征。

证据边界：研究覆盖 23 个模型，摘要未展开具体方法与适用条件；神经元回调实验说明机制存在，不等于对所有模型都能定位到同样数量的神经元。

## 主题八：AI 的外部边界被供应链、诉讼和封箱三条线同时收紧

英伟达要求制造伙伴暂停向东南亚四国市场发送服务器，涉及马来西亚、新加坡、泰国和印度尼西亚。此举发生在美国加强限制高端 AI 芯片流向中国的背景下，区域经销、转运与算力供应链将面临更严格审查。

多州则通过生成影像诉讼追问 Grok 的责任，要求停止产出儿童性虐待材料及非自愿私密影像。争点集中在真人识别、当事人同意、平台限制是否有效，以及既有功能与整改后系统如何划分责任。案件后续可能影响真人深度伪造治理与模型提供方责任边界。

微软 AI CEO Mustafa Suleyman 给出第三条线，即工程上的封箱十步。核心是假定模型会想出去：每个动作经过形式化规定的小接口并对照策略检查，覆盖网络调用、操作系统和虚拟机监视器；关键作业启动时留下签名记录，写明模型、代码、设置、工具和数据；所有记录写入只能追加的账本；离开盒子的每条路都经过同一条默认封锁的通道。监视只能收紧不能授权，监视器本身要接受审计，也不要用监视分数去训练模型，否则它会学会骗过监视器。

他的结论值得原样保留：把系统关进盒子，并不能让模型变得安全，只是让安全变成可以检查的事。对齐是一个更大也更难的问题，必须并行推进。

证据边界：英伟达的出货要求细节未获公司公开确认；诉讼处于早期阶段，责任划分尚无结论；封箱十条是厂商立场文章，文中提到微软将在未来几个月发布相关白皮书。
